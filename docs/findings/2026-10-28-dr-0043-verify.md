# サイドバーの区画と GLOBALS (DR-0043) を実機で確かめた

- Date: 2026-10-28
- 対象: 作業コピーの daemon (v0.200.0) を隔離して起動し (`CCMSG_STATE_DIR` / `CCMSG_CONFIG_DIR` / `CCMSG_DATA_DIR` を一時ディレクトリ、HTTP は `127.0.0.1:18642`、tailscale の自動許可は無効)、playwright-cli の Chromium で webui を開いた
- 繋ぎ先の候補: `CCMSG_HTTP_ALLOW_ORIGIN="http://verify-a.localhost:18642, http://verify-v6.localhost:18642"`。`*.localhost` は Chromium が loopback に解決し、名前は `localhost` そのものではないので候補に入る (= 同じ daemon に別の origin で届く)
- セッションの行: `CCMSG_CLAUDE_CONFIG_DIRS` に一時ディレクトリの fixture の config dir を 1 つだけ渡し、`sessions/<pid>.json` を `sleep` のプロセス 4 つの pid で書いた (sid は乱数、名前は `🤖ccmsg-verify-dr43-<n>`、版と `startedAt` は 1 時間ずつずらす)。実 config dir は daemon に見せていない。Status タブを描くために、うち 1 つに 1 行だけの transcript を置いた
- (e) の回だけ daemon の `HOME` を実 HOME にした (`claude update` を実際の install に効かせるため)。それ以外の回は `HOME` も一時ディレクトリ。どちらの回もセッション検索の対象は fixture の config dir だけ
- スクリーンショットは作業の一時ディレクトリに残した (リポには入れない)

## `claude update` の実行 (1 回だけ)

- 隔離 daemon の環境の `PATH` は `~/.local/bin` を含み (`ps eww` で確認)、`which -a claude` はこの Mac の native installer の `~/.local/bin/claude` (→ `~/.local/share/claude/versions/2.1.312`) の 1 つだけ。daemon は `Bun.which("claude", { PATH })` でこれを使う
- 押してから daemon.log の行までの実測は **1.6 秒**。既に最新 (2.1.312) で、取得は起きていない (symlink と `claude --version` は前後で同じ 2.1.312)
- 取得が起きる回は新しい版が出ていないので測れていない。`claude_update_timeout` の 300 秒は DR-0043 §6 の見積もり (264 MB を 2 MB/s で約 130 秒の倍強) のまま

## 縦積みの一覧の既定の高さ (DR-0043 Consequences)

390x844、フォーム (Session Search) を開いた縦積みで測った。

| 既定の高さ | 一覧の上端から 1 行目 | 行のピッチ | SESSIONS の本体の下 (ROOMS・GLOBALS の見出しと段の余白) | 見える行 |
|---|---|---|---|---|
| 220px (区画の列の前の値) | 71px | 59px | 80px | 1 行と 2 行目の上 10px |
| 292px (新しい既定) | 71px | 59px | 80px | 2 行と 3 行目の上 23px |

区画の列の前は「上端から 1 行目まで 75px、220px で 2 行 + 3 行目が覗く」だった。ROOMS と GLOBALS の見出しが SESSIONS の本体の下に来るぶん、同じ見え方には 72px 多く要る。

- 既定値は localStorage / sessionStorage に値が無い時だけ使われる。測った時点の Sidebar は mount のたびに今の値を両方に書いていたので、既にこの webui を開いた端末は 220px を覚えている。書き込みは人がスプリッターを動かした時だけに直した (storage.ts の「レイアウト寸法」の規則どおり) が、既に書かれた値を消す移行はしないので、それらの端末は 220px のまま (スプリッターで動かせば変わる)

## 確かめていないこと

- Safari (iOS / macOS) での `hidden="until-found"` とページ内検索 (`beforematch`)。Chromium では属性値が付くことだけ確かめ、ページ内検索で開く操作は unit test (happy-dom で `beforematch` を投げる) だけ
- `claude update` が取得を伴う回の所要時間 (上記)
- `claude update` の失敗の表示を実機で起こすこと。失敗の文言と次の成功で消えることは unit test (`packages/webui/test/sidebar-folds.dom.test.ts`)、daemon 側の 6 つの error code は `packages/daemon/test/claude-update-op.test.ts`
