# TL のツールバーが狭い幅で 2 段になる: flex-wrap はチップが縮む前の幅で段を割り振る

- Date: 2026-11-12
- 対象: ccmsg v0.260.0 の webui (`.tl-toolbar`、`SearchBar` の `.search-bar` / `.search-bar-chips` / `.search-bar-chip`)、playwright-cli 0.1.22 の Chromium 155 (headless) と WebKit (Safari 26.6 相当)
- 動機: kawaz の iPhone (幅 430) のスクリーンショットで、TL のツールバーの 2 段目に ⤒ ⤓ だけが落ち、1 段分の高さを使っていた。1 段目の検索条件のチップは省略記号で切れており、右に空きがあった
- 方法:
  - 隔離 daemon (作業コピーの `packages/daemon/src/index.ts --foreground`、`HOME` / `TMPDIR` / `CCMSG_STATE_DIR` / `CCMSG_CONFIG_DIR` / `CCMSG_DATA_DIR` を一時ディレクトリ、`CCMSG_CLAUDE_CONFIG_DIRS` に試験用の config home だけ)。試験用の config home に `sleep` の pid の `sessions/<pid>.json` を 3 つ書き、transcript を置いた (A: 40 往復と未読の say、B: 40 往復、C: 400 往復)。直す前は main の workspace、直した後は作業コピーの daemon を別のポートで並べて同じ fixture を読ませた
  - headless・DPR 3・高さ 800 で、幅 430 / 390 / 375 / 320 / 1280 について次の状態のツールバーを測った
    - 検索なし
    - チップ 1 つ (`👺\s*[A-Za-z]+\s+nomatch`、正規表現、0/0)。未読の say がある / 無い、🔔 のフィルタ中
    - 一致あり (`👺\s*Hello`、1/40)
    - 件数が広い (`lorem`、↓ を 11 回押して 12/400)
    - 短い語 (`foo`、`ab`、`a`)
    - 検索の入力を開いた状態
    - チップ 3 つ (`lorem dolor nomatchword`)
  - 段の数はツールバーの中の押せるもの (バッジ・🔍・チップ・件数・↑ ↓・⤒ ⤓) の縦の中心が何種類あるかで数えた。あわせて 300〜560 を 5px 刻みで掃いて、段の数と横へのはみ出し (ツールバーの右端を越える子・ページの横スクロール) を見た

## 何が幅を取っていたか

- `.tl-toolbar` の `flex-wrap: wrap` は、子を flex base size (`.search-bar` は `auto` なので max-content) で段に割り振る。チップは `max-width: 14ch` で省略表示になっていても、段の割り振りは 14ch の幅で行われ、縮む (flex-shrink) のは割り振りの後なので、縮める前に ⤒ ⤓ が次の段へ落ちる
- 今の並びで 1 段に収まるのに要るツールバーの幅 (px):

| 状態 | Chromium | WebKit |
|---|---|---|
| チップ 14ch・0/0 | 423.1 | 431.1 |
| `lorem`・12/400 | 389.8 | 397.8 |
| チップ 14ch・12/400 | 445.7 | 453.7 |
| `👺\s*Hello`・1/40 | 402.3 | 412.3 |

- WebKit は 🔔🔐 の箱が Chromium より 6px 広く (66.8 / 60.8)、幅 430 では 0/0 でも 1px 足りずに 2 段になる。kawaz のスクリーンショット (1290px = 430 の 3 倍) はこれ

## min-content を「チップは下限、他は中身」にする形

- flex の nowrap の箱の min-content は、子の min-content contribution の和になる。`white-space: nowrap` の文字の min-content は全文の幅なので、チップに `min-width` を付けても min-content は縮まない (両ブラウザで実測)
- grid の列を `minmax(L, max-content)` にすると、その列の min-content は L、max-content は中身になる (両ブラウザで実測)。チップの行 (`.search-bar-chips`) をこの grid にし、`.search-bar` を `flex: 1 1 0` (min-width: auto) にすると、ツールバーは「チップを L まで縮めた幅」で段を割り振る。`.search-bar` は `max-width: max-content` まで伸び、余りは ⤒ ⤓ の `margin-left: auto` に回る
- チップが 2 つ以上の時は、語が多いと下限の合計でも 1 行に入らない。grid は折り返せず横へはみ出すので、この時は今の flex-wrap のまま並べる

## 下限 L と、効かせる幅

- CSS では下限を「チップの幅と L の小さい方」と書けない (`min()` は max-content を取れない)。L より短い語のチップは L まで広がる
- L は ASCII 3 字の語のチップの幅を下回る最大の切りのよい値にした: 字の 1.5em (`1.5 * var(--font-size-sm)` = 18px) + 左右の padding と枠 = 36px。チップの幅 (px、両ブラウザで同じ):

| 語 | チップ | 下限 36px での広がり |
|---|---|---|
| `foo` | 36.27 | 0 |
| `say` | 37.19 | 0 |
| `abc` | 38.72 | 0 |
| `OK` | 35.17 | +0.8 |
| `TL` | 32.42 | +3.6 |
| `ab` | 32 | +4 |
| `W` | 29.63 | +6.4 |
| `検` | 30 (WebKit 29.09) | +6 (WebKit +6.9) |
| `a` | 24.63 | +11.4 |
| `ill` | 27.05 | +9 |

- 3 字でも幅の狭い字だけの語 (`ill`、`iii`) は広がる
- 広がりを狭い幅だけに閉じるため、grid の形は `@container tl-toolbar (width < 30rem)` の中でだけ効かせる。30rem (480px) は上の表の最大 (WebKit のチップ 14ch・12/400 で 453.7) より広く、この幅以上では今の並びのままで 1 段に収まる。300〜560 の掃引でも、480 以上は全部の 1 語の状態で両ブラウザとも 1 段だった
- 下限の近くでは 1 字と省略記号が見える (WebKit の幅 362 でチップ 36.75px、`👺…`)。1 語・0/0 で 1 段に収まるのは Chromium は 355 まで、WebKit は 365 まで

## 確かめていないこと

- iPhone の実機の Safari (字の幅・🔔🔐 の箱の幅が手元の WebKit と違えば、段の変わり目の幅がずれる)
- 件数が 4 桁を超える時 (`123/4567`)
- ダークテーマ (色だけで寸法は同じはず)
