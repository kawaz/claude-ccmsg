## DR の想定と違ったこと

### model の上書きの後、own の model が上書きの model になる

- 📌sonnet で 1 回応答すると、transcript の assistant 行の `message.model` が `claude-sonnet-5-5` になる。daemon の `contextWithFacts` は context の model を transcript のまま (応答した model) にするので、status snapshot の `context.model` も sonnet になる
- webui はそれをセッション自身の model として読むので、model の select は `session: 📌fable,📌opus,🏛️sonnet,📌haiku`、default は `sonnet-5-5` (無印)、状態行も `sonnet-5-5` で `⁺` が付かない (m1、m2)。engine 自身の model は fable のまま
- 🏛️sonnet で通しを外した直後は、default が `📌fable-5-1` になった (module が報告する通しの値はセッション自身の model、比べる相手は transcript の sonnet)
- 🏛️ の位置 (§6.2、裁定 18) と状態行の印 (§5) が、model の上書き中は正しい値を指さない。直し方は判断待ち (下の「未確定」)

### effort の own が module の読み直し直後に実効値に落ちる

- effort の own は module の facts の effort (差し替える前の `e.effort`) で、無い時は transcript の行の effort (差し替えた後の実効値)
- 試験中に別の作業で plugin の版が上がり、module が読み直されて facts が空になった。その直後、`⏱️max` の turn の後の状態行が `max` (無印) になった。次の main thread の request で facts に effort が入ると `low` に戻った

## 未確定

- 1 回目の (d) では、🏛️ の [適用] (05:34:59、applied、両タブ `low`) の後、同じ turn の次の request (05:35:11、Read の tool_result) が `effort: max` だった。この request の直後に、別の作業の版上げで module が読み直された (`plugin.json changed — reloaded`、新しい run id の名乗りは 05:35:11.527)。module の読み直しを伴わない 2 回 (通し無し、通し 📌medium の上) では、同じ手順の次の request は `low` だった。1 回目の `max` が読み直しと関係するかは確かめていない
- 版上げで隔離 daemon が `graceful shutdown (upgrade)` で止まり、試験セッションが自分の env で daemon を起こし直した (1 回目は `CCMSG_HTTP_BIND` を渡していなかったので HTTP 無し、`HOME` は実 HOME)。その daemon は止め、2 回目からは試験セッションにも `CCMSG_HTTP_BIND` と `CCMSG_CLAUDE_CONFIG_DIRS` を渡した
- main thread でない request (入力の候補を作る request、最後の user の文が `…no quotes or explanation.`) は、上書きが効いている間も `low` のままだった。subagent と同じく素通しになっているが、`agentId` があるのか別の経路なのかは見ていない
