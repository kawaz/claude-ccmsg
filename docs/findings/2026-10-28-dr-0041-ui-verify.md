# DR-0041 §6 の select (FAB の effort、Status タブと状態行の通し) を実機で確かめた

- Date: 2026-10-28
- 対象: Claude Code 2.1.312。daemon は隔離して起動 (`CCMSG_STATE_DIR` / `CCMSG_CONFIG_DIR` / `CCMSG_DATA_DIR` を一時ディレクトリ、HTTP は `127.0.0.1:18642`、`HOME` は一時ディレクトリ、`CCMSG_CLAUDE_CONFIG_DIRS` は試験用の config dir だけ)。webui は playwright-cli の Chromium で開いた (タブ 0 は Timeline、タブ 1 は Status)
- 試験用セッション: 一時ディレクトリの中で hyoui の下に `claude --name "🤖ccmsg-verify-effort-ui-<n>" --plugin-dir <コード> --model fable --effort low --permission-mode default`。`CLAUDE_CONFIG_DIR` は一時ディレクトリの config dir (`settings.json` は theme と空の `enabledPlugins` だけ、認証情報は写していない)。セッションにも隔離 daemon と同じ `CCMSG_*` (`CCMSG_HTTP_BIND` と `CCMSG_CLAUDE_CONFIG_DIRS` を含む) を渡した
- コード: 表の観測は、この変更の commit を一時 workspace に取り出し、daemon も `--plugin-dir` もそこから起動して取った。共有の作業コピーには別の作業の未 commit の変更 (module → daemon の経路) が入っていて、それを `--plugin-dir` にした回は module の返事が daemon に届かなくなった (`request-override … unconfirmed`)
- Messages API の代役: `ANTHROPIC_BASE_URL` を手元の HTTP server に向け、request の `model` と `output_config.effort` を記録して、`ok (model=… effort=…)` を返す。最後の user の文に `TOOLWAIT` があれば、権限確認が要る Bash の tool_use を返す (権限確認の間は turn が止まるので、その間に操作して、許可した後の同じ turn の次の request を見る)
- 人の入力は `hyoui input` で打った。テキストと select の中身は DOM (`button.override-value` の文字、`optgroup` の label と `option` の文字、`document.activeElement`) で読んだ。`showPicker()` で開くネイティブの一覧はスクリーンショットにも DOM にも出ないので、開いたことは確かめていない
- スクリーンショットは作業の一時ディレクトリに残した (リポには入れない)。下の表のファイル名はその名前

## 未確定

### リセットした後の同じ turn の次の request が `max` のことがある

- (d) の手順を、通しの有無・許可までの間隔 (2〜4 秒と 10 秒以上) を変えて約 14 回やった。3 回、🏛️ の [適用] が `applied` で返り、両タブが `low` になった後に、許可した後の同じ turn の次の request (tool_result を運ぶもの) が `effort: max` だった。他は `low`
- `max` だった 3 回は、どれも代役が受けた最後の user message が tool_result だけだった。`low` の回は同じ user message に送った文も入っていた。transcript の行の並び (user → tool_use → tool_result → 応答) と `api-request` の `params` の項目は、どちらの回も同じ
- `max` の後も、webui の状態行と select は `low` のまま (module の facts の effort、つまり差し替える前の `e.effort` は `low`)。module は単発を外したと facts で伝えているのに、request は `max` で出たことになる。module が素通しにした request に engine が turn の前の差し替えの値を使っているのか、module の側の問題かは切り分けていない (module の turn.step の入力と出力の記録が要る)
- 1 回目に `max` が出たのは、別の作業の版上げで試験セッションの module が読み直された時と重なっていた。clean な workspace (読み直しなし) でも 4 回のうち 1 回で出た

### その他

- 版上げで隔離 daemon が `graceful shutdown (upgrade)` で止まり、試験セッションが自分の env で daemon を起こし直した (`CCMSG_HTTP_BIND` を渡していない回は HTTP 無し、`HOME` は実 HOME)。その daemon は止め、以後は試験セッションにも `CCMSG_HTTP_BIND` と `CCMSG_CLAUDE_CONFIG_DIRS` を渡した
- main thread でない request (入力の候補を作る request、最後の user の文が `…no quotes or explanation.`) は、上書きが効いている間も `low` のままだった。素通しになっているが、`agentId` があるのか別の経路なのかは見ていない

## 確かめていないこと

- `showPicker()` で一覧が開くこと (ネイティブの一覧は DOM にもスクリーンショットにも出ない)。Safari の `HTMLSelectElement.showPicker` の有無と、無い時に focus だけが残る振る舞い
- Safari でのネイティブ `<select>` の `<optgroup>` の描き方と、テキストの絵文字の幅
- FAB の 📌 / 🏛️ で `request_override` の返事が `applied` 以外になる場合の FAB の注記 (unit test `packages/webui/test/session-input-composer.dom.test.ts` でだけ確認)
