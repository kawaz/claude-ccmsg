# daemon が push の行から say を鳴らし、未読と既読を持つ形 (DR-0045 の段階 3) を実機で確かめた

- Date: 2026-10-28
- 対象: Claude Code 2.1.312、hyoui 0.16.4。ccmsg の作業コピーで、v0.208.0 の上に段階 3 の say・permit の音声・既読の commit を載せたもの。launch の節は、その上に `launch_tool` を足した作業コピー (2026-10-29)
- 動機: [DR-0045](../decisions/DR-0045-say-speaks-in-tool-shown-from-transcript.md) の §6 と §7 を、本物の claude と webui で通して次を見る
  - daemon が push の行の say の tool_use を見つけて、1 度だけ、辞書を当てて鳴らすこと
  - permit の音声を daemon が鳴らすこと
  - 未読と既読が `ev:"say_unread"` / `say_read` で webui に出て、別タブにも効くこと
  - daemon を再起動しても、既読が残り、古い say を鳴らし直さないこと
  - 旧版の plugin の CLI の `ccmsg say` が、新しい daemon の下でも鳴ること
  - launch の起動コマンドの所要時間 (`LAUNCH_TOOL_WAIT_MS` を決める材料)と、tool `launch` が同期で返ること・待ちを超えた起動の結果が知らせで届くこと
- 方法:
  - daemon: 作業コピーの `packages/daemon/src/index.ts --foreground` を起動した。`CCMSG_STATE_DIR` / `CCMSG_CONFIG_DIR` / `CCMSG_DATA_DIR` / `HOME` は一時ディレクトリに向けた。`CCMSG_CLAUDE_CONFIG_DIRS` には試験用の config home だけを名指した。`CCMSG_SAY_BIN` には、時刻と argv をファイルに足すだけの shell script を置いた (音は出さない)
  - 辞書: `<config dir>/say-dictionary.tsv` に `push<TAB>プッシュ` の 1 行を置いた
  - 試験用の config home: `settings.json` は普段の設定から `apiKeyHelper` と `env` の `ANTHROPIC_*` と hooks と statusLine を抜き、plugin を全部無効にした。`.claude.json` に onboarding 済み、ダミー鍵の承認、作業ディレクトリの trust を置いた
  - 試験セッション `🤖ccmsg-verify-stage3`: tmux の中で `env -i` から起動した。`--plugin-dir <作業コピー>`、`--model sonnet --permission-mode default --debug`、`--allowedTools` に ccmsg の say / permit / launch と Agent を渡し、daemon と同じ `CCMSG_*` を付けた
  - model の応答: Messages API の代役 (reference `claude-mods/lab-setup`) が返した。prompt の最後の行の印で返す内容を分けた: `SAY:<文>` は say の tool_use、`PERMIT:<voice>` / `PERMIT0` は permit の tool_use、`SUBSAY:<文>` は Agent の tool_use で、その subagent は say を呼ぶ
  - 観測:
    - 発声の記録ファイル
    - user role で daemon の socket に繋ぎ、`ev:"say_unread"` と `ev:"permit_request"` の push を時刻付きで記録する小さなスクリプト
    - `say_read` を送るスクリプト
    - webui を `playwright-cli` の名前付きセッション 2 つ (同じ TL を開いた 2 タブ) で開き、TL の本文・既読ボタン・Sessions 一覧の `未読の say N 件` を読んだ
    - daemon.log

## 判明した事実

| 確かめたこと | 期待 | 実際 | 根拠の観測 |
|---|---|---|---|
| say の発声 | push の行の tool_use で、辞書を当てて `--` の後に鳴る | `-- デーモン に プッシュ しました` が鳴った。tool の結果は「読み上げを依頼した (daemon が読み上げ、webui に 🔔 で出る)」 | 発声の記録と試験セッションの画面 |
| `-` で始まる本文 | say の option にならない | `-- -v で始まる文` で鳴った | 発声の記録 |
| permit の音声 (voice あり) | voice を辞書付きで鳴らす | `-- プッシュ の許可をお願いします` が鳴った。permit の記録の push とほぼ同時 | 発声の記録と `ev:"permit_request"` の時刻 |
| permit の音声 (voice なし) | 固定文を鳴らす | `-- 許可を求めています` が鳴った | 発声の記録 |
| subagent の say | 鳴るが、未読に入らない | `-- subagent から デーモン へ` が鳴った。その後の `say_unread` は main の 2 件のまま | 発声の記録と push の記録 |
| 未読 | live のセッションの main thread の say が `say_unread` で届く | 最初の say の後に 1 件、2 つ目の say の後に 2 件が届いた。ts は jsonl の行の時刻 | push の記録 |
| `say_read` | 知らない id は全部断る。既読は書いてから答える。二度押しは無変化 | 知らない id は `invalid_args` (`no say with id toolu_nope`)。既知の id は `{ok:true}` で、`say-read.json` の `read` に入った。二度目の push は来なかった | スクリプトの返事、ファイル、push の記録 |
| TL の 🔔 | say の tool_use の行の位置に描く。既読は 🔕 | 既読にした say は 🔕 (ボタンの代わりに「既読」の表示)、未読の say は 🔔 と既読ボタン。本文は原文のまま (`daemon に push しました`) | webui の本文 |
| 「N 件すべて既読」 | 最新の未読のボタンだけが N 件、他は「既読」 | 未読 3 件で、ボタンは `既読` / `既読` / `3 件すべて既読` | webui のボタンの文 |
| 別タブ | 片方で押すと、もう片方も 🔕 になる | タブ A で「3 件すべて既読」を押すと、A と B の両方で既読ボタンが 0、🔕 が 4、Sessions 一覧の未読の印が消えた | 2 つの playwright セッションの本文 |
| Sessions 一覧の件数 | `say_unread` をセッションごとに数える | `未読の say 1 件` / `未読の say 3 件` と、未読の数で出た | webui の aria-label |
| daemon の再起動 (既読) | 既読が残る | 再起動の後の最初の `say_unread` は、既読にしなかった 1 件だけだった | push の記録 |
| daemon の再起動 (発声) | 追いつきで読んだ古い say を鳴らし直さない | 再起動を 3 回して、発声の記録は増えなかった | 発声の記録 |
| daemon の再起動 (タブ) | 開いたままのタブが、再接続で未読を取り戻す | 再起動の直前に作った未読の say が、開いたままのタブで既読ボタンと `未読の say 1 件` のまま出た | webui |
| 旧版の CLI の `ccmsg say` | 新しい daemon に op `say` を断られても鳴る | 0.208.0 の plugin の `bin/ccmsg say "旧版の push"` は exit 0 で鳴った (`旧版の プッシュ`、旧版の CLI の辞書が当たった)。daemon.log に `request say ... refused: op: unknown op: say` が出た | 発声の記録と daemon.log |

### launch (`launch_tool`)

- 方法: daemon の config の `session_launcher` に、同梱の起動コマンド (`default-launch-command.ts`、`hyoui run --detached -- claude …`) を包んだ script を置いた。script は起動される claude を試験用の config home と代役 API に向け、`HYOUI_STATE_DIR` を一時ディレクトリにした。待ちを超える場合は、同じ script の前に 17 秒の `sleep` を入れた script を使った (遅い起動コマンドの代わり)

| 確かめたこと | 期待 | 実際 | 根拠の観測 |
|---|---|---|---|
| 起動コマンドの所要時間 (user role の `session_launch`、続けて 5 回) | 数秒以下 | 411 / 40 / 44 / 55 / 45 ms。最初の 1 回は hyoui の server の起動を含む。5 回とも exit 0 で、`session_id` が返り、hyoui に 5 つの claude が立った | 計測スクリプトと `hyoui list` |
| tool `launch` (待ちの内) | 同期で `{ session_id, exit_code, stdout, stderr }` の JSON が返る | 返った (`exit_code: 0`、新しい `session_id`)。daemon.log の `session_launch: by=<試験セッションの sid>` | 試験セッションの画面と daemon.log |
| tool `launch` (待ちを超える) | 15 秒で「まだ終わっていない」を返し、起動が終わった時に結果が会話に届く | 15 秒で「起動コマンドがまだ終わっていない。結果は終わった時に ccmsg からこの会話に届く」が返った。依頼の 18 秒後に `launch_tool: told <sid>: delivered`、会話に `Message from @ccmsg-daemon: ccmsg の launch (cwd: …) が終わった: …` が入り、その知らせで次の turn が始まった | 試験セッションの画面と daemon.log |

### 直した不具合: 終了の時に空の未読をタブに配っていた

- 起きた場面: daemon の終了 (再起動)。終了の時に relay の fold を閉じるので、未読の集合が空になり、その空の `say_unread` を接続中のタブに配っていた。タブは次の daemon が自分の未読を送るまで、全部の say を 🔕 として見せる
- 修正前の観測: 修正前の daemon を止めた時、観測スクリプトに `{"ev":"say_unread","says":[]}` が届いた。daemon.log の `graceful shutdown` と同じ時刻だった
- 修正: 終了の途中では `say_unread` を配らない (`daemon.shuttingDown` を見る)
- 修正後の観測: 修正後の daemon を止めた時は、観測スクリプトに空の push が来なかった。届いたのは、次の daemon の購読の時の 1 件だった。daemon のテスト (`say: a daemon that shuts down`) は、修正を外すと落ちることを確かめた

## 確かめていないこと

- subagent からの launch の結果が、その subagent に知らせとして届くこと。daemon のテストは、届けられない時に daemon.log に残ることだけを見ている

- subagent の TL の say が既読ボタンを持たない 🔕 で出ること。webui の単体テストだけで確かめていて、ブラウザでは見ていない
- 追いつきの最中に compaction の再 push が来た時の発声。追いつきが未読の古い say を読み終わる前にその行が push されると、鳴りうる
