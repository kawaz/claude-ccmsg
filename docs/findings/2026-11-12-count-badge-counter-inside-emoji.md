# 🔔🔐 の赤いカウンターが絵文字の絵の右へはみ出す: 絵文字の字の送りは描かれた絵より広い

- Date: 2026-11-12
- 対象: ccmsg v0.259.0 の作業コピーの webui (`CountBadge`、`.count-badge` / `.count-badge-counter`)、playwright-cli 0.1.22 の Chromium (headless shell)・Google Chrome 157 (headless)・WebKit (Safari 26.6 相当)、macOS の Apple Color Emoji
- 動機: kawaz のスクリーンショットで、Sessions の行の 🔔 の赤いカウンター「1」が鈴の絵の右へはみ出し、鈴と repo 名の間が文字で書いた「🔔kawaz」より空いて見えた。カウンターは箱 (`.count-badge`) の右下 (`right: 0; bottom: 0`) に置いてあり、箱の中には収まっていたので、箱と目に見える絵の関係を測る
- 方法:
  - 隔離 daemon (作業コピーの `packages/daemon/src/index.ts --foreground`、`HOME` / `CCMSG_STATE_DIR` / `CCMSG_CONFIG_DIR` / `CCMSG_DATA_DIR` を一時ディレクトリ、`say_command` は `/usr/bin/true`)。fixture は daemon の UDS に session として hello し run を名乗る 3 つの live のセッションで、それぞれ未読の say と許可依頼 (transcript の `permit` の行) を 1 / 12 / 100 件ずつ書いて push した
  - headless・DPR 2・viewport 1280×800・dark で `/s/<sid>` を開き、Sessions の行 3 つと TL のツールバーのバッジを測った
  - 絵の範囲: そのバッジの絵文字以外を `visibility: hidden` にしてスクリーンショット (device scale) を撮り、背景色との差 (RGB の差の和 > 60) がある画素の外接矩形を絵の範囲とした。カウンターも隠した状態で測る
  - 比較の文字: 同じ font の span に「🔔kawaz」を書き、鈴の絵の右端から k の絵の左端までを同じ方法で測った
  - kawaz のスクリーンショットは同じ方法で列ごとの画素の種類 (絵 / 赤い枠 / 白い字) を並べて読んだ

## 絵文字の字の送りと描かれた絵 (16px、bell は 🔔)

単位は px。「右の空き」は箱の右端から絵の右端まで。

| ブラウザ | 箱の幅 (字の送り) | 絵の幅 | 絵の左の空き | 右の空き | 絵の下端 (箱の下端から) | 文字の「🔔kawaz」の鈴から k まで |
|---|---|---|---|---|---|---|
| Chromium (headless shell) | 20 | 15.5 | 0.5 | 4 | 0.5 上 | 5 |
| Google Chrome 157 | 20 | 15.5 | 0.5 | 4 | 0.5 上 | 5 |
| WebKit | 23 | 19.5 | 1.5〜2.5 | 1〜2 | 1.5〜2.5 下 (箱の外) | 3 |

字の大きさを変えた時の右の空き (bell、Chromium / WebKit、px): 14px は 4 / 1.5、15px は 4 / 1、16px は 4 / 2、17px は 4 / 1.5、18px は 3 / 2、24px は 0 / 1.5。🔐 と 😀 も 16px で同じ傾向 (Chromium 4〜4.5、WebKit 2〜2.5)。

- Chromium は小さい字で絵を 1em 角で左に寄せて描き、字の送りを 4px 足す。WebKit は絵を 1em より大きく (16px で 19.5px) 描き、字の送りの中でほぼ中央に置く
- `text-rendering` (geometricPrecision / optimizeSpeed / optimizeLegibility)、`font-optical-sizing: none`、`font-kerning: none`、`font-feature-settings: 'trak' 0`、`font-variation-settings: 'opsz' 32`、`font-family: "Apple Color Emoji"` の直指定、VS16 (U+FE0F) のどれでも、両ブラウザで値は変わらなかった
- 字の送りと絵の差がブラウザと字の大きさで違い、CSS から絵の範囲を得る手段が無い。直す時は、どのブラウザでも越えない量 (最大の空き) だけ枠を寄せる

## kawaz のスクリーンショット

列の画素の並びから (スクリーンショットの画素)。

| 量 | 行のバッジ | 文字の「🔔kawaz」 |
|---|---|---|
| 鈴の絵の幅 | 約 59 | 59 |
| カウンターの幅 | 34 | — |
| カウンターの右端 − 鈴の右端 | 約 +6 | — |
| 鈴 (またはカウンター) の右端から次の字まで | 17 (カウンターから) | 10 (鈴から) |

- カウンターの幅 / 鈴の幅は 0.58、文字の鈴から k まで / 鈴の幅は 0.17。WebKit の 16px (11.44 / 19.5 = 0.59、3 / 19.5 = 0.15) と合い、Chromium (11.44 / 15.5 = 0.74、5 / 15.5 = 0.32) とは合わない。kawaz の画面は WebKit (Safari) の描き方と整合する (どのブラウザかは未確認)
- はみ出しの 6 は鈴の幅の 0.10 で、WebKit の 16px の鈴 (19.5px) に直すと約 2px。WebKit の直す前の測定 (1〜2px) と同じ大きさ。カウンターの高さでは鈴の胴は裾より細いので、目にはこれより大きくはみ出して見える

## 直す前と直した後

直し方: `.count-badge-counter` を `right: 0; bottom: 0` から `right: 4px; bottom: 1px` にした (箱・字の大きさ・色・角丸は同じ)。

列: 箱の幅、絵の幅、右の空き、カウンターの幅、枠の右端 − 絵の右端 (正ならはみ出し)、枠の下端 − 絵の下端 (正ならはみ出し)、文字の鈴から k まで。単位は px。

- 直した後、両ブラウザの全ての場合で枠の右端 ≤ 絵の右端、枠の下端 ≤ 絵の下端。WebKit では枠が絵の内側へ 2〜3px 入る
- カウンターを `display: none` にした時と比べ、両ブラウザで、行とツールバーの高さ、バッジの組の幅、各バッジの箱の位置と大きさ、次の要素 (repo 名 / 次のバッジ / ツールバーの次の道具) の左端の差は全て 0px
- バッジの箱の幅は文字の「🔔」の字の送りと同じ (Chromium 20px、WebKit 23px)。行の鈴と repo 名の間には行の gap (4.8px) が今までどおりある
- 選択中のバッジ (`?filter=say`) の accent の面と枠は箱の外側の box-shadow のままで、直す前と同じ位置に出た

## 99+ は絵の幅に収まらない

`99+` の枠は 22.84px で、絵 (Chromium 15.5px、WebKit 19.5px) より広い。右端を絵に合わせると左へはみ出す。

| ブラウザ | 🔔 の 99+ の左端 − 行のアイコンの右端 | 🔐 の 99+ の左端 − 🔔 の絵の右端 |
|---|---|---|
| Chromium (前) | +1.95 (重ならない) | +1.15 (重ならない) |
| Chromium (後) | −2.05 (アイコンに 2px 重なる) | −2.85 (鈴に 2.85px 重なる) |
| WebKit (前) | +4.96 | +1.16 |
| WebKit (後) | +0.95 | −2.85 (鈴に 2.85px 重なる) |

収め方は kawaz の裁定待ち (実装していない)。

## 確かめていないこと

- 実機の Safari (macOS / iPad) での値。WebKit は playwright の WebKit で測った
- ブラウザのズーム (Cmd +) を掛けた時。Chromium は字の大きさで右の空きが変わる (18px で 3px、24px で 0px) ので、ズームで描く大きさが変わると枠は絵の内側へ深く入る (はみ出す向きには動かない)
- Apple Color Emoji 以外の絵文字の font (macOS / iOS 以外)
