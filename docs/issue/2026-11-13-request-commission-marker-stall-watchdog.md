# 返事が要る依頼にマーカーを付け、END が無いまま受け手が止まったら送り手に知らせる

## 概要

返事が必要な依頼に依頼マーカー `COMMISSION_<ランダム 8 文字 lowercase>` を付け、受け手には完了報告で `END_COMMISSION_<id>` を返させる。END が来ないまま受け手が止まったら、仕組みの側から送り手に自動で知らせる。

部外者 (hyoui リポの統括セッション) からの依頼なので、実装方法は断定しない。対象コードを読んで裏取りしてから採否を決めてほしい。

## 背景

2026-11-12〜13 の実例。

- hyoui の統括セッションが worker (in-process の teammate) に時間のかかる作業を頼んだ
- worker は計測を裏で回し、その完了通知を待ってターンを終えた
- 計測は終わったが完了通知が worker に届かず、worker は約 7 時間待機したままだった
- 統括も worker の報告で起こされる形だったので気づかなかった
- 統括には worker の待機通知 (「計測の完了を待っています」) が 2 回届いていたが、正常な待ちと読んで放置した
- 対処として統括が 25 分ごとに自分で起きるタイマーを張った。常に張るのはコストがかかり、正常な時に無駄な通知が出る

kawaz の案 (2026-11-13):

1. メインロールのルールに「返事が必要な依頼には依頼マーカー `COMMISSION_<ランダム 8 文字 lowercase>` を SendMessage / ccmsg send の本文に含め、受け手には完了報告で `END_COMMISSION_<id>` を返させる。依頼への質問の返信には END を含めさせない」を足す
2. 仕組みの側は、エージェント間メッセージに依頼マーカーを見つけたら記録し、END が来ないまま受け手のトランスクリプトに 25 分動きがなければ、依頼の送り手に「依頼マーカーに END がないまま、そのエージェントが 25 分動いていません」と自動で通知する

## 検討点 (起票元の統括の所見。採否は任せる)

- **(a) 判定の起点**: 「トランスクリプトに動きがない」は、長い前景コマンドを待っている正常な worker でも成り立つ。今回の停止は「ターンを終えて待機に入ったまま、起こす通知が来なかった」形だった。「END が無いままターンが終わり、その後 25 分再開していない」を条件にすると、前景で実行中の worker には飛ばない
- **(b) END の拾い方**: 依頼文に「末尾に END_COMMISSION_xxx を付けて」と書くので、依頼文にも END の文字列が入る。worker が質問の中で引用しても閉じてしまう。拾う対象を「受け手から送り手への返信の、最終行に単独で書かれた END」に限ると誤って閉じない
- **(c) 追い依頼**: 同じ worker に追加の指示を何度も送る (実例で 5 回以上)。依頼ごとに ID を管理すると受け手がどの END を返すか迷う。「送り手と受け手の組ごとに開いている依頼は 1 つ、新しいマーカー付き送信が上書き」が単純。ID は通知文と検索用
- **(d) 防げないもの**: END の付け忘れ (誤通知 1 回で済む)。中間報告に END が付いてきた場合は、送り手が続きの返信に新しい依頼マーカーを付ければ監視が戻る (kawaz 2026-11-13)。END 付きの報告は送り手に届くので送り手はその時点で起きており、「新しいマーカー付き送信が開く」という作りのままで足りる。仕組み側に追加は要らない。ルール側に「END 付きの報告を受けて、まだ作業が続くなら、新しい依頼マーカーを付けて返す」を書く
- **(e) 置き場**: ccmsg の daemon は send を見ていて、タイマーを持て、送り手を起こす手段 (send) がある。未確認なのは次の 3 点
  - 同じプロセス内の SendMessage の観測方法 (hook でツール呼び出しを拾って daemon に知らせる形になるはず)
  - teammate / subagent のターン終了を拾える hook があるか
  - 受け手のトランスクリプトの場所の引き方

## 受け入れ条件 (案)

- [ ] マーカー付きの依頼を受けた agent が END を返さずに待機したまま 25 分経つと、送り手のセッションが通知で起きる
- [ ] 正常に END を返した依頼では何も通知されない
- [ ] 前景で長いコマンドを実行中の受け手には通知されない
- [ ] 依頼文の中の END 文字列と、質問の返信の中の引用では閉じない

## ccmsg の外で要るもの

claude-rules-personal の統括ロールのルールへの追記。仕組みの形が決まってから書く。

- マーカーの付け方
- END の返させ方
- END 付きの報告を受けて、まだ作業が続くなら、新しい依頼マーカーを付けて返す
- 「依頼が開いたままの待機通知を受けたら、待っている対象が動いているかを 1 回確かめる」
