# 💬 のフィルタで、スレッドを開くと押したコメントが上下に動く / 行の位置で開いた直後に着地先が画面の外

解決済みにした時のスクロールの動きを測っている途中で見つかった、別の 2 件。どちらも v0.380.0 からあり、原因は追っていない。

## 観測 1: スレッドを開くと、押したコメント自身が画面上で動く

💬 のフィルタで、ホイールで位置を寄せた後に人のコメントを押してスレッドを開いた時の、押したコメントの画面上の上端の動き (390 幅、隔離環境)。

| 版 | Chromium | WebKit |
|---|---|---|
| v0.384.0 | 下へ 63px | 下へ 93px |
| v0.380.0 | 下へ 24px | 上へ 69px |

押した場所から指やカーソルの下の項目がずれる。

## 観測 2: 行の位置とフィルタを付けた URL で開くと、着地先が画面の外のまま

`/timeline/<行の uuid>?filter=comment` の形で開いた直後に、scrollTop が 0 のままの時があった。着地先の項目の上端は 1045px で、画面の外だった (v0.380.0)。

## 未特定

- 観測 1 の原因。選んだ吹き出しを画面の中央へ寄せる既存の選択の動き、開いたスレッドの全文表示 (高さの制限を外す) による高さの変化、返信が間に挿し込まれることのどれが効いているか
- 観測 2 の原因。💬 のフィルタは並びを CSS の `order` で入れ替えているので、着地の計算が DOM の順と見た目の順の違いを踏んでいる可能性があるが、確かめていない
- 観測 2 が常に起きるのか、条件があるのか

## 特定に要る観測

- 観測 1: スレッドを開く前後で、押したコメントより上にある項目の高さの合計がどう変わるか。選択の「中央へ寄せる」を切った時に動きが消えるか
- 観測 2: 着地の処理 (行への移動) が、フィルタの中でどの要素の位置を読んでいるか。`order` を外した並びで同じ URL を開いた時に着地するか

## 関連

- 解決済みにした時に TL が末尾へ飛ぶ動きは、スクリプトでスクロールしてスクリプトでボタンを押した時にだけ起きる (末尾への保持が、人の操作の印 `wheel` / `touchstart` / `pointerdown` / `keydown` で外れる作りのため)。人の操作では再現しなかった。実機の iOS Safari のタッチと支援技術での操作で、これらの印が必ず出るかは確かめていない
