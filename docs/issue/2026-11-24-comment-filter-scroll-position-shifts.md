# 💬 のフィルタで、スレッドを開くと押したコメントが上下に動く / 行の位置で開いた直後に着地先が画面の外

解決済みにした時のスクロールの動きを測っている途中で見つかった、別の 2 件。どちらも v0.380.0 からあり、原因は追っていない。

## 観測 1: スレッドを開くと、押したコメント自身が画面上で動く

💬 のフィルタで、ホイールで位置を寄せた後に人のコメントを押してスレッドを開いた時の、押したコメントの画面上の上端の動き (390 幅、隔離環境)。

| 版 | Chromium | WebKit |
|---|---|---|
| v0.384.0 | 下へ 63px | 下へ 93px |
| v0.380.0 | 下へ 24px | 上へ 69px |

押した場所から指やカーソルの下の項目がずれる。

## 観測 2: 行の位置とフィルタを付けた URL で開くと、着地先が画面の外のまま

`/timeline/<行の uuid>?filter=comment` の形で開いた直後に、scrollTop が 0 のままの時があった。着地先の項目の上端は 1045px で、画面の外だった (v0.380.0)。

## 未特定

- 観測 1 の原因。選んだ吹き出しを画面の中央へ寄せる既存の選択の動き、開いたスレッドの全文表示 (高さの制限を外す) による高さの変化、返信が間に挿し込まれることのどれが効いているか
- 観測 2 の原因。💬 のフィルタは並びを CSS の `order` で入れ替えているので、着地の計算が DOM の順と見た目の順の違いを踏んでいる可能性があるが、確かめていない
- 観測 2 が常に起きるのか、条件があるのか

## 特定に要る観測

- 観測 1: スレッドを開く前後で、押したコメントより上にある項目の高さの合計がどう変わるか。選択の「中央へ寄せる」を切った時に動きが消えるか
- 観測 2: 着地の処理 (行への移動) が、フィルタの中でどの要素の位置を読んでいるか。`order` を外した並びで同じ URL を開いた時に着地するか

## 調査の結果 (2026-11-24)

隔離環境の fixture (人のコメントが 2 つのスレッド、btw の問答とそれへの返信、スレッドを持たないコメント) で、Playwright の Chromium と WebKit、390 幅と 1280 幅で測った。押す前の位置はホイールで寄せ (人の操作の印が出る)、コメントの本文を押した。スレッドの根と 2 つ目のコメントを 12 行にして高さの抑えが掛かる写しでも測った。

### 観測 1 の原因

1. **選択を中央へ寄せる動きが、💬 のフィルタの中で押した時にも走っていた**。選択が変わるたびに選んだ吹き出しを scroller の上下の真ん中へ smooth で寄せる処理 (項目の 💬 や Files の 💬 から来た時のためのもの) が、フィルタの中の押下でも同じに効いていた。証拠: 押した後の上端は押す前の位置に依らず一定 (Chromium 390、根のコメント: 押す前 200 / 450 → 押した後どちらも 351.2。スレッドを持たないコメント: 200 / 450 → 382.1)。中央へ寄せる 1 行だけを切った版では、根とスレッドを持たないコメントの動きが 151 / -99 と 182 / -68 から 0 になった
2. **押したコメントより上の項目が伸びる**。中央へ寄せる動きを切っても、上に開くものがあると押したコメントが下がる。2 つ目のコメントを押すと、その上 (根の直後) にエージェントの返信が出る: 上の項目の高さの合計が 638 → 785 (+147) で、押したコメントは +152.2 下がった (押す前 450 の時)。btw の答えへの返信を押すと、上の btw の項目が答えを出して 170 → 381 に伸び、+211.5 下がった。ブラウザの scroll anchoring が打ち消すこともある (2 つ目のコメントを押す前 200 の時は 0.2) が、どの要素を基準に選ぶかで変わり当てにならない
3. **全文になることによる高さの変化**。開いたスレッドの項目は高さの抑えが外れる。12 行の写しでは根のコメントが 322 → 1042 に伸び (Chromium 390)、1 の中央へ寄せる計算はこの伸びた吹き出しを真ん中に置くので、上端が画面の外 (-68.8) に出た。2 つ目のコメントを押すと、上で根が全文になり返信が出て、上の高さの合計が 758 → 1625 (+867) になった

v0.384.0 の「下へ 63px / 93px」は、1 の中央へ寄せる動きの量 (押す前の位置と真ん中の差) に 2 と 3 が重なったもの。

### 観測 2 の原因

1. **着地がコメントの記録より先に走る**。webui は transcript の読み込みの応答 (開いてから約 120ms) で行を描き、そこで位置の行へ着地する (約 160ms)。コメントの記録 (`ev:"comments"`) はその後 (約 166ms) に届く。着地した時点では記録から描く項目が無く、行の列の高さは 707px (記録が揃った後は 3431px)、着地先のスレッドの並びの位置も揃った後と違う
2. **記録が届くと、着地先の行の要素が作り直される**。コメントのブロックの行は、記録があればコメントの付け先 (`CommentTargetScope` の target) を持つ。この部品が target の無い時は Fragment、有る時は Context の Provider を返していたので、記録が届いて target が付いた時に部品の種類が変わり、中の項目の要素が外されて新しい要素になっていた。証拠: MutationObserver で、記録が届いた直後に着地先の要素が行の列から外れたのを記録した (Chromium、記録の着信 166ms、外れたのが 205ms)。フィルタの無い位置の URL (`/timeline/<行の uuid>`) でも直す前の版は着地が外れ (Chromium 390 幅、着地先の上端 368px、狙いは 127px)、直した版は着地した (127.1px) ので、`order` による並べ替えは原因ではない
3. **位置の保持は、要素が DOM から外れると手放す作り**。着地は useScrollHold で保たれ、内容が伸びるたびに置き直されるが、狙う要素が DOM から外れた時点で手放す。作り直された後は誰も置き直さず、記録で伸びた内容に合わせてブラウザが scrollTop を動かした (scrollTo も scrollTop への代入も呼ばれずに 10 → 2757、または 0 のまま)

**起きる条件**: 人のコメントの行 (コメントのブロックだけの人の発言の行) へ着地し、その後にコメントの記録が届いた時。この fixture では毎回この順で、Chromium と WebKit の両方・390 幅と 1280 幅で、根の行と 2 つ目の行の各 3 回の全部が外れた (Chromium 390 幅で、根: scrollTop 0 のまま上端 629px。2 つ目: 末尾へ行き上端 -2018px。どちらも狙いは 164px)。transcript の応答だけを 400ms 遅らせて記録を先に届けると、直す前の版でも狙いどおり着地した (164.2px)。

### 直した内容

- 観測 1: 💬 のフィルタの中で人のコメントを押した時 (項目の押下と、頭の「💬 コメント」の開閉のボタン) は、押した項目の scroller の上端からの距離を押した時に測り、スレッドが開閉した描画の後もその距離を保つ (フィルタを外す時と同じ `holdScrollAnchor`、一瞬)。中央へ寄せる動きは、項目の 💬・範囲の 💬・Files の 💬 から選んだ時だけに残した。保つのは押した要素でなく項目: 開閉のボタンは開くとラベルに替わり、要素が無くなるため
- 観測 2: `CommentTargetScope` が target の有無に関わらず Provider を返すようにした (無い時は null を渡す)。記録が後から届いても行の要素は同じままで、着地の保持が外れない

### 直した後の実測

- 観測 1: 押す前後の押したコメントの上端の動きは、Chromium で最大 0.5px、WebKit で最大 0.9px (390 幅と 1280 幅、根・2 つ目・btw の項目・btw の答えへの返信・スレッドを持たないコメントを押す前 200 と 450 の位置から押した時、別のスレッドを開いた後に押した時、開いたスレッドの根を押して閉じた時、キーボードの Enter と開閉のボタンで押した時)。直す前の同じ場面では -519〜+226px 動いた
- 観測 2: 着地先の上端は、狙い (ツールバーの下端 + `scroll-margin-top`) との差が Chromium で 0.3px 以内、WebKit で 0.7px 以内 (390 幅と 1280 幅、根の行と 2 つ目の行の各 3 回)

### 残ったもの

- 記録が届いて並びの位置 (`order`) だけが変わり、どの項目の高さも変わらない場合、useScrollHold は大きさの変化しか見ないので着地を置き直さない。この fixture では記録で項目が増えて高さが変わるので起きず、確かめていない
- 実機の iOS Safari のタッチでは確かめていない (Playwright の WebKit だけ)
- 💬 のフィルタで隠れる行 (エージェントの応答の行) を位置にした URL では、着地先が描かれず先頭か末尾に留まる。この issue の 2 つとは別の話で、手を付けていない

## 関連

- 解決済みにした時に TL が末尾へ飛ぶ動きは、スクリプトでスクロールしてスクリプトでボタンを押した時にだけ起きる (末尾への保持が、人の操作の印 `wheel` / `touchstart` / `pointerdown` / `keydown` で外れる作りのため)。人の操作では再現しなかった。実機の iOS Safari のタッチと支援技術での操作で、これらの印が必ず出るかは確かめていない
