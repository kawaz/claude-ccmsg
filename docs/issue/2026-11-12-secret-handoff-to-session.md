# webui から秘密の値をセッションのエージェントに渡す (daemon が預かり、CLI のパイプで取り出す)

## 概要

kawaz が手元の秘密の値 (token、API key 等) を、リモートの webui からセッションのエージェントに渡す口を作る。会話の本文に一度も書かず、システムのクリップボードも通さない。

## 背景 (kawaz 2026-11-12)

原文: 「秘密情報をエージェントに渡すツールが欲しい。ローカルなら簡単なんだがリモートだと一度晒す形の手段以外は面倒なので。手軽なのが欲しい。」「Status とかに貼り付け用の input を最初から置いてありゃいいか」。最初の案は daemon が受けた値を pbcopy に流す形だったが、統括の案 (daemon が預かり CLI のサブコマンドで取り出す) で合意した。kawaz「僕もそれが良いと思ってたサブコマンドのやつ。説明の簡単のためにクリップボードにしたけど」。

## 決まったこと

- webui のセッションの画面に、貼り付けだけを受ける受け口を最初から置く (ボタンで開く形にしない)。打鍵は受けない。受けたら「N 文字を受けた」と破棄のボタンを出す
- 値はシステムのクリップボードに書かない (履歴ツールに残る、ユニバーサルクリップボードで渡りうる、ホストの全セッション・全アプリが読める)。daemon がメモリに預かり、ディスクに書かない
- エージェントは ccmsg の CLI のサブコマンドからパイプで取り出す (例: `ccmsg secret take | gh auth login --with-token`)。値を tool の結果で返すと会話に入るので、tool にはしない。DR-0039 §4 (CLI は人の口と module の transport だけ) の例外として DR に理由を書く
- daemon.log、request の記録、trace に値を書かない。仕組みで保証してテストで固定する
- エージェントには、値をパイプで使い、表示しない (echo や打ち返すコマンドに渡さない) と伝える

## 決めること (統括の推し、kawaz の返事待ち)

- 預け先: 貼り付けた webui で開いているセッションに限る (その subagent も同じ session id なので取り出せる)
- 知らせ方: 預かった時に daemon がそのセッションへ知らせを自動で送る (使い方と「表示しない」の決まりを含む)
- 消えるタイミング: 1 回取り出したら消える。取り出されなくても 5 分で消える。webui に「預かり中 (残り N 分)」と破棄のボタン
- 一度に預かれる数: 1 つ。新しく貼ったら前の物を捨てる

## 確かめること

- iOS の Safari で、打鍵を受けない受け口に貼り付けのメニューが出て、中身を取れるか (実機)
- 取り出すセッションの同定 (CLI がどのセッションから呼ばれたかを daemon がどう確かめるか)

## 任意 (足すかは別判断)

- 預かった値が万一 tool の結果に出た時に、module の request の書き換え (hooks/request-override.ts) で API へ送る前に伏せる安全網
