# WebKit の 390px 幅で、画面の下端の ☰ のメニューが上へ折り返さず吹き出しに重なる

## 観測 (2026-11-15、headless の WebKit、v0.267.0 の作業中)

- TL の assistant の吹き出しの ☰ を、画面の下端に置いて押すと、メニューは画面の中には収まるが、上へ折り返さずに ☰ の行と吹き出しを覆う (☰ 823.9〜843、メニュー 716.8〜844)。項目は押せる
- Chromium の 390px と、両エンジンの 1280px では、上へ折り返して画面の中に収まる
- WebKit の 390px では ☰ の右端が x=261.9 で、メニューの幅は 277px。`position-try-fallbacks` の候補 3 つがどれも横に収まらず (左に 15px、右に 121px はみ出る)、最初の配置のまま画面の中へずらされている、と計測から見ている
- v0.267.0 で入れた `anchor-scope` が起こしたものではない。それまではメニューが文書の最後の ☰ に吊られていて、この形が外から見えなかった

## 分かっていないこと

- 実機の iPhone の Safari で同じになるか (直した後の形も実機では見ていない)

## 原因 (2026-11-19 に確かめた)

- ☰ は足元の行のツールバーの右端にあり、x はツールバーのタブの数で決まる。Chromium にはブラウザ内の翻訳 (Translator API) があるので翻訳のタブが `original` / `ja(browser)` / `ja(host)` の 3 つ、WebKit には無いので `original` / `ja(host)` の 2 つになり、`ja(browser)` の幅 (約 79px) と間隔のぶん ☰ が左に寄る (390px 幅で Chromium 316.7〜344.5、WebKit 234.1〜261.9)。☰ の位置の計算がずれているのではない。iPhone の Safari にも Translator API は無いので、同じ並びになる見込み
- ☰ の右端 262 に対してメニューの幅は 277px なので、☰ の右端揃え (`bottom span-left`) は左に、左端揃え (`flip-inline`) は右に溢れ、縦だけを折り返した候補も同じ横の配置なので溢れる。候補がどれも溢れるとブラウザは最初の配置 (☰ の下) を使って画面の中へずらすので、画面の下端では ☰ に重なる

## 決めること

- 直す (統括の決定)。JS で位置を計算せず、折り返しの候補を足す

## 対処 (2026-11-19)

- `packages/webui/src/public/app.css` の `@supports` の節に `@position-try --tl-msg-menu-wide { position-area: bottom span-all; justify-self: anchor-center; }` を置き、`position-try-fallbacks` の最後に `--tl-msg-menu-wide`、`--tl-msg-menu-wide flip-block` を足した。横を画面の幅いっぱいにして ☰ の中心に揃えるので横には溢れず、縦の折り返し (下 → 上) だけで収まる。端揃えの候補が先なので、横に収まる画面の開き方は変わらない
- テスト `packages/webui/test/timeline-rendering.dom.test.ts` で候補の並びと `@position-try` の定義を固定した (happy-dom は `@position-try` を規則として残さないので定義は app.css の字で見る)。開く位置はブラウザで測った
