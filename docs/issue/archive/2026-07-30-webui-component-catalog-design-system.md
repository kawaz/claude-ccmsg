# webui のデザインシステム / コンポーネントカタログ導入

## 概要

webui のコンポーネント・画面デザインが場当たり的に積み上がっており、一貫性を保つ
恒常的な仕組み (デザインシステム / コンポーネントカタログ) を導入する。

## 背景

kawaz r76m76, 2026-07-30:

> 404と403のデザインがバラバラなのが気になる。場当たり的にデザインしてる感が強い。
> デザインシステムやストーリーブックなどを導入したくなりますね。そろそろコンポーネント数も
> 多く画面構成も複雑になってきてるので。

即効対応としてエラービューの統一は別途実施 (r76m76 起点の error-view-unify)。
本 issue はその先の恒常的な仕組み。

### 選択肢 (メイン推し順)

1. **自作カタログページ (推し)**: webui 自身に /catalog 的なルートを足し、主要コンポーネントを
   状態別に並べる。Bun バンドルにそのまま乗る (ビルド基盤追加ゼロ)、実 CSS/実テーマで見える、
   playwright での visual 検証にもそのまま使える。既存の isolated daemon 検証フローと相性が良い
2. **Ladle**: Storybook 互換の軽量版 (Vite ベース)。導入コスト中、ビルド系が Bun.build と二重になる
3. **Storybook 本体**: エコシステム最大だが重く、preact + Bun 構成との摩擦が最も大きい

合わせて、デザイントークン (色/間隔/字形) の整理を app.css の CSS 変数ベースで行い、
コンポーネントはトークンだけを参照する規約を敷く (これはどの選択肢でも共通の下ごしらえ)。

## 進捗

方向は案1（webui 自身に /catalog ルートの自作カタログ）で着手。kawaz r115 の E→D 順序承認に基づく。
まず既存部品棚卸し + デザイントークン整理 → カタログルート実装の順。
