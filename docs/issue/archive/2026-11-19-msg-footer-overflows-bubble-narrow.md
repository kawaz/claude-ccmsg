# Chromium の 390px 幅で、assistant の吹き出しの足元の行が吹き出しより右へはみ出る

## 観測 (2026-11-19、headless の Chromium、390px 幅、☰ のメニューの折り返しを直す作業の途中で見つかった)

- 足元の行 (時刻、翻訳のタブ、☰ の並ぶ行) の幅が 333px で、吹き出しの右端 (322.6px) より約 22px 右へはみ出る
- Chromium にはブラウザ内の翻訳 (Translator API) があるので、翻訳のタブが original / ja(browser) / ja(host) の 3 つになり、WebKit (2 つ) より行が長い

## 分かっていないこと

- はみ出しが見た目で問題になるか (吹き出しの外の余白の中に収まっているか)
- 足元の行は吹き出しの幅に合わせて折り返すべきか、吹き出しの外へ伸びてよいか

## 見た目 (2026-11-19、headless、390px 幅)

- はみ出しは吹き出しの外の余白 (画面の右端まで 45px) に収まり、画面の右端や他の要素には当たっていなかった。それでも ☰ (316.7〜344.5) の大半が吹き出しの枠の外に出て、吹き出しに付いた操作に見えない
- 統括の決定で、足元の行は吹き出しの幅の中に収め、収まらない時は折り返すのを既定にした

## 原因

- 吹き出し (`.tl-bubble`) は縦の flex で `align-items: flex-start` なので、足元の行 (`.tl-bubble-footer`) の幅は中身に合わせた幅 (fit-content) になり、最小でも中身の最小幅 (min-content) まで広がる
- 足元の行は `flex-wrap: wrap` で時刻とツールバーを別の行に折り返せるが、ツールバー (`.tl-msg-toolbar`) は折り返さない flex だったので、ツールバー全体の幅 (333px) がそのまま足元の行の最小幅になり、吹き出しの幅 (311px、列の 85%) を超えた
- WebKit はブラウザ内の翻訳が無く、翻訳のタブが 1 つ少ない (ツールバー 250px) ので吹き出しに収まっていた

## 対処

- ツールバーに `flex-wrap: wrap` を足し、タブの組 (翻訳のタブ / md|source / ☰) の切れ目で折り返すようにした。ツールバーの最小幅が一番広い組の幅になるので、足元の行は吹き出しの幅に収まる
- 収まる幅では折り返さないので、WebKit の 390px と両エンジンの 1280px の形は変わらない (下の表で座標が同じ)
- `packages/webui/test/timeline-rendering.dom.test.ts` の「the bubble footer's toolbar wraps between its tab groups instead of widening the bubble」で、ツールバーと足元の行の `flex-wrap` の算出値を固定した (直す前の app.css で落ちることを確かめた)
