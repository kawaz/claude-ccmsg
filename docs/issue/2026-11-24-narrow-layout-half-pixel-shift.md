# 720px 以下の幅で、本文が左に 0.5px はみ出し、右に 0.5px の隙間が出る

## 観測

2026-11-24、e2e の `tl-panels` の webkit の 1 件 (390px で TL のパネルの境目をドラッグすると、木の幅が期待の 95 でなく 94.5 になる) を調べた時の実測。

- 720px 以下の幅では、サイドバーの幅が画面の 85% になる。390px では 331.5px
- `#layout` の横スクロールの位置は整数に丸まる
- その結果、本文 (`main.session-view`) が左に 0.5px はみ出し、右に 0.5px の隙間が出る。セッションの画面 (`.session-panes`) の左端は -0.5px にある
- chromium と webkit の両方で観測した。v0.360.0 でも同じ

## 影響

見た目では分かりにくいが、位置を測る処理が半端な値を受け取る。上の e2e は、WebKit が渡すポインタの位置 (整数) から、左端の -0.5px を引いて 94.5 になっていた (テストの側は、整数の位置へ動かして木の右端がそこに来ることを確かめる形に直した)。

## 直し方の方向 (未検証)

サイドバーの幅を、割合のままでなく整数の px に丸める (CSS の `round()` 等)。丸めた時に、広い幅や他の幅の指定とぶつからないかは確かめていない。

## 出どころの実測 (2026-11-24)

隔離 daemon と e2e の harness で、Chromium 159 と WebKit 27.2 の両方で測った (幅ごとに同じ値)。720px 以下の幅で `#layout` の子はサイドバーと本文の 2 つだけで、本文の幅は画面の幅 (整数) に一致する。ずれは、サイドバーの幅 (`--drawer-width` = 画面の 85%) の端数と、整数に丸まった横スクロールの位置 (= サイドバーの幅を丸めた値) の差そのものだった。端数の向きによって本文は左にも右にもずれる。

| 画面の幅 | `--drawer-width` | 横スクロールの位置 | 本文の左端 |
|---|---|---|---|
| 375 | 318.75px | 319 | -0.25 |
| 384 | 326.4px | 326 | 0.390625 |
| 390 | 331.5px | 332 | -0.5 |
| 393 | 334.05px | 334 | 0.046875 |
| 414 | 351.9px | 352 | -0.109375 |
| 430 | 365.5px | 366 | -0.5 |
| 400 | 340px | 340 | 0 |

## 直した内容

app.css の 720px の `@media` で、サイドバーの幅を `round(down, …, 1px)` で整数の px に切り捨てた。直した後は上の幅のどれでも、`.session-panes` と本文の左端が 0、右端が画面の幅になる (両ブラウザ)。721px と 1280px の横並びの幅は変わらない。e2e の `tl-panels` に、390px で `.session-panes` の左端が 0 であることの確かめを足した。
