# TL で tool_use と tool_result を全部の tool で組にして表示する

## 概要

今、呼び出しと結果を 1 つのカードに組にして出すのは Bash と Read だけで、それ以外の tool は呼び出しの fold と `tool_result` の fold が別々に並ぶ。kawaz の案 (2026-11-14) は、全部の tool で組にすること。裁定待ちの点が 2 つ残っていて、実装には着手していない。

## 今の実装 (2026-11-14 にコードで確認)

- Bash: コマンドのカードの中に出力を入れ、結果の行は省く。バックグラウンドの Bash は結果が後から来るので、結果を別に残して「結果へ」のリンクで結ぶ
- Read: 読んだファイルの中身をカードの中に出し、結果の行は省く
- それ以外: モデルの上では呼び出しに結果を結び付ける所まで済んでいる (`packages/webui/src/client/transcript-model.ts` の `resolveToolResults`、segment `tool-use` の `result`)。描画がそれを使っておらず、結果は `tool_result` の fold のまま

## kawaz の案 (2026-11-14 の原文の要点)

- tool_use と tool_result が並んでいたら、Bash のように表示する
- 並んでいない場合、tool_use 側は use だけを表示し、結果の欄は 1 行にする
  - 結果が未着: 「実行中... 5s」(カウントアップ)
  - 結果あり (閉じている): 「▶︎結果表示 [結果へ移動]」
  - 結果あり (開いている): 「▼結果表示 [結果へ移動]」の下に結果の中身
- tool_result 側は、上下セットのアイテムを置く。分離した result には右側に印を置き、押すと tool_use へ飛べる (一瞬のスムーススクロール)。tool_use 側にも対の印を置き、相互に飛べるようにする
- 印の文言は提案を求められた (「async result だと長い」)

## 統括の評価と案 (kawaz には提示済み、返事待ち)

賛成。Bash のバックグラウンドの「結果へ」を全部の tool に広げて双方向にした形で、今の作りとつながる。

- 印の案: 呼び出し側 `↓結果`、結果側 `↑呼出`。「async」は Bash のバックグラウンド実行と紛れ、並列に呼んだだけで離れた場合は非同期でもないので、離れている理由を名乗らない
- 呼び出し側の「[結果へ移動]」と印は同じ働きなので、呼び出し側は `↓結果` 1 つにまとめられる

## 決めること

- [ ] 「並んでいる」の定義。並列に 3 つ呼ぶと transcript は「呼出 A・B・C、結果 A・B・C」の順で、厳密な隣接だと並列の呼び出しは全部「離れている」になる。統括の推しは「間に吹き出し (本文や user の発言) が挟まらなければ並んでいる」
- [ ] 結果側に「入力も一緒に出す」(上下セット) という読みで合っているか

## 統括の推しで進める点 (異論が無ければ)

- カウントアップは live のセッションの未着分だけ。中断されたターンや終わったセッションは、今の Bash と同じ「結果なし」
- 呼び出し側で開いた時の結果の中身は、開いた時にだけ描く (大きい結果で DOM が倍にならないように)。画面内検索の一致は結果側だけで数える
- 飛び先が読み込みの窓の外 (過去分の側) にある時は、スムーススクロールでなく位置の URL への移動 (過去分を読み込んで着地)
- 専用の表示がある tool (Read、Edit / Write の diff、ccmsg の send / say / permit、subagent) は今のまま。対象は汎用の fold と Bash
