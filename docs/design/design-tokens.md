# デザイントークン (webui)

webui の見た目の素材は `packages/webui/src/public/app.css` の `:root` に定義した
CSS 変数 (トークン) に集約する。**コンポーネント側の CSS はトークンだけを参照し、
色・余白・文字サイズの生値を書かない。**

## トークン一覧

### 色

`--bg` / `--bg-alt` / `--fg` / `--fg-muted` / `--border` / `--accent` / `--accent-fg` /
`--danger` / `--warn` / `--fg-strong` と、吹き出し用の `--user-bubble-bg` / `--peer-bubble-bg` /
`--assistant-bubble-*` / `--agent-comm-*`、検索ハイライト用の `--search-*`。
`@media (prefers-color-scheme: dark)` で同じ名前を再定義するので、**色は必ず
トークン経由で参照する** (生値を書くとダークテーマで破綻する)。

`--fg-strong` は `--fg` より地から遠い側に置いた「本文より濃い文字色」。
system-ui の 400 と 700 の差は本文サイズでは小さく、太さだけの強調は地の文に
沈むので、**太さと濃さを同時に当てる**ために使う (markdown の `strong`、表の
見出しセル)。地の文には使わない — 全部が濃いと濃さが情報でなくなる。

### 面の色 (`--md-surface`)

markdown の装飾 (inline code / ブロックコード / 引用 / 区切り線 / 表の罫と
見出しセル / `<details>` パネル) だけは、**絶対色ではなく「いま自分が載って
いる面からの距離」で持つ**。`--md-surface` がその面の色で、装飾は
`color-mix(in oklab, var(--md-surface), var(--fg) N%)` で導出する。

| 役割 | N |
|---|---|
| 地 (inline code / 表の見出しセル) | 8〜9% |
| 地 (ブロックコード / `<details>` パネル) | 5% |
| 地 (引用の帯) | 4% |
| 罫 (inline code / 表 / `<details>`) | 20〜24% |
| 罫 (区切り線・引用の左罫) | 22〜28% |

面積が広いものほど N を小さく取る (同じ濃さだと重くなる)。N の実測は
プレビュー / 吹き出し × ライト / ダークの 4 通りで、地の差が oklab の L で
0.058〜0.069 に収まることを確認した値。絶対色だった頃は同じ 4 通りで
0.013〜0.038 とばらつき、白地のプレビューでは装飾が地の文とほぼ同色だった。

**宣言する責務は md を載せる容器の側にある。** 容器は自分の `background` の
すぐ隣で `--md-surface` を同じ値に宣言する (離すと面色だけ変えたときに装飾が
取り残される)。容器が背景を持たないときは `:root` の既定値 (`--bg`) が効く。

対象は上記の markdown 装飾だけで、**意味を持つ色は相対化しない** —
`--accent` (リンク)・`--danger` / `--warn`・`--fg-strong`・Shiki の
シンタックス色は面が変わっても同じ意味なので、絶対トークンのまま参照する。

### 余白 (padding / margin / gap)

| token | 値 | 主な用途 |
|---|---|---|
| `--space-1` | 0.1rem | アイコン・バッジの内側の詰め |
| `--space-2` | 0.15rem | 同上 |
| `--space-3` | 0.2rem | 小さいボタン、インライン要素の間隔 |
| `--space-4` | 0.25rem | 行内の要素間 |
| `--space-5` | 0.3rem | リスト行の縦詰め |
| `--space-6` | 0.35rem | 同上 |
| `--space-7` | 0.4rem | 標準的な小余白 |
| `--space-8` | 0.5rem | 最頻出。ボタン・入力欄の内側 |
| `--space-9` | 0.6rem | ブロック間の間隔 |
| `--space-10` | 0.7rem | 同上 |
| `--space-11` | 0.75rem | パネル・カードの内側 |
| `--space-12` | 0.9rem | セクション間 |
| `--space-13` | 1rem | セクション間 (広め) |
| `--space-14` | 1.25rem | 画面端の余白 |
| `--space-15` | 1.5rem | 大きめのブロック間 |
| `--space-16` | 2rem | 画面レベルの余白 |
| `--space-17` | 3rem | 空状態など特に広い余白 |

段が細かいのは、この UI が情報密度の高いリスト・タイムライン中心で、
0.05rem (0.8px) 単位の差が実際に意味を持って使われているため。
新しい UI を足すときは **近い段を選ぶ**。段の間の値が必要になったら、
その必要性を疑ってから段の追加を検討する (段を増やすより既存段に寄せる)。

### 文字サイズ

| token | 値 | 主な用途 |
|---|---|---|
| `--font-size-3xs` | 0.6rem | 最小のメタ情報 |
| `--font-size-2xs` | 0.65rem | バッジ・補助ラベル |
| `--font-size-xs` | 0.7rem | 補助テキスト |
| `--font-size-sm` | 0.75rem | UI ラベル |
| `--font-size-md` | 0.8rem | 本文 (最頻出) |
| `--font-size-lg` | 0.85rem | 強調した本文 |
| `--font-size-xl` | 0.9rem | 小見出し |
| `--font-size-2xl` | 1rem | 見出し |
| `--font-size-3xl` | 1.15rem | 大見出し |
| `--font-size-4xl` | 1.25rem | 画面タイトル |

### 行間

| token | 値 | 主な用途 |
|---|---|---|
| `--md-leading` | 1.75 | 読み通す本文 (ファイルプレビューの markdown) |
| `--md-leading-tight` | 1.6 | 拾い読みする本文 (Timeline の markdown) |

行間そのものより **段落間隔との比** が読みやすさを決める。段落間隔は必ず
行間より広く取る (同じだと段落の切れ目が行の切れ目に埋もれる)。同じ理由で、
見出しの上余白は下余白より広い (見出しは直後の本文に属する)。この 2 つの
不等号は密度の違う文脈でも共通で、変えるのは値だけ。

UI 部品の行間 (`line-height: 1` のバッジ等) はこの段に乗せない — あちらは
「文章の密度」ではなく「箱の高さ」の話なので、生値のままでよい。

## 規約

- padding / margin / gap / font-size は `var(--space-N)` / `var(--font-size-*)` を書く
- 色も同様にトークン参照 (ダークテーマ対応のため必須)
- tsx 側の `style` 属性に余白・文字サイズを直書きしない。CSS クラスへ寄せる
- md を載せる容器は `background` の隣で `--md-surface` を宣言する
- 機能固有の寸法 (`--composer-fab-size` 等) は `:root` に専用変数として置き、
  値そのものはスケールに合わせる必要はない

## 例外 (トークン化しない生値)

- **1px / 2px / 3px のヘアライン**: 境界線・ドット等、rem スケールに乗せると
  かえってぼやける値
- **負の margin**: `calc()` 経由の参照が読みにくくなるため生値のまま
- **スケール下限 (0.1rem) 未満**: `0.05rem` の詰めは丸めると見た目が変わる
- **一点物の大きな値**: `12rem` のスクロール余白、`4rem` / `2.6rem` の
  インデント上限、`1.6rem` / `1.8rem` / `2.6rem` の表示用フォントサイズ。
  スケールに載せる意味がないので生値 + コメントで残す
- **`em` 指定**: 親フォントサイズに対する相対指定は意図的なのでそのまま
