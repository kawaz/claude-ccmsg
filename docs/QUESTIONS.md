## 裁定待ち

### AGY-Q5 待機中の teammate と終わった subagent に、agy の応答の本文をどう届けるか

「全部 append、止まっている相手は `.` で起こす」と決まった ([DR-0066](./decisions/DR-0066-agy-conversation-tool.md) K14) が、この 2 つの相手への append は `no running loop` で断られる (実測)。足してから起こす順では本文を足せない。DR-0066 の Q17。

- [ ] a: 先に `.` で起こし、その agent の turn の始まりで append する (本文は append のまま。起こした turn の最初の request に載るかは実測が要り、載らなければ teammate では失われる。module が本文を turn の始まりまで持つ)
- [ ] b: この 2 つの相手にだけ、本文を `agent.send` で送る (推し。届くことは実測済みで、足す仕組みが無い。本文は親からの文の枠の中で読まれる。K11 の時の発言「turn 停止中のワーカーの場合はソケット経路で投げる」と同じ形)

### AGY-Q6 最後の応答の最中に足した append が読まれないまま turn が終わる場合

足した時は走っているので `.` では起こさない。本体と subagent は次に別の契機で turn が始まった時に読み、teammate は読まない (実測)。DR-0066 の Q18。

- [ ] a: 足した後に、次の request が無いまま turn が終わったのを見て `.` で起こす (取りこぼしが無くなる。append ごとに turn の終わりまで見張る仕組みが要り、K14 で消した見届けに近い)
- [ ] b: この隙間を受け入れる (推し。作りは K14 のまま。応答は依頼の記録に残り status で読める。teammate は読まない)
- [ ] c: 止まっているかによらず、append の後に毎回 `.` を送る (足した時の判定が要らない。走っている相手は `.` だけの turn を余分に持つ。teammate の読まれない append は救えない)
