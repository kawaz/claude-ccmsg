# DR-0068: TL のエージェントの応答に既読の印を付け、既読の応答・say・許可依頼を 1 行だけの吹き出しに畳む

- Status: Proposed
- Date: 2026-11-26

未実装。kawaz の依頼 (2026-11-26) を元に起草したもので、kawaz の確認の前。Decision は kawaz の依頼と、それを受けた統括の整理でできている。kawaz が言ったことは「kawaz 2026-11-26」、統括が kawaz に示して否定されなかったものは「統括案、kawaz の異論なし」、依頼に無く統括が根拠を書いて決めたものは「統括の判断」と書く。

## Context

kawaz の依頼 (2026-11-26) の要点:

- TL の通常の応答にも、解決済み ([DR-0062](./DR-0062-comments.md) §6) とは別の「✔️既読」のボタンがあってよい。どうでもよい報告で TL が流れるのを非表示にできれば、必要な返信を探すのが楽になる
- 既読にした応答は消さず、中身が次の 1 行だけの吹き出し (1 行だけのメッセージの吹き出しに見える形) で並べる。本文を数行だけ残して切る形ではない。押した時だけ開いて元の吹き出しに戻り (一瞬でなく、1 行から元の高さへ縦に伸びる)、状態は変わらない。外すのは吹き出しの右下のボタン

  ```
  （✅ 既読: 別の issue にしました (docs/issue/2026-11-26-i…）
  （✅ 既読: 待機通知に注記を足す処理の実装の報告が届きました (comm…）
  ```

- 既読は say や許可依頼にも置いてよい。それらには既読が既にあるので、融合するか別扱いにするかは任せる
- キーはそのメッセージの uuid で、状態は既読の uuid の集合を持てば足りる。見た目は webui の側で作る

解決済みのスレッドの吹き出しを 1 行だけの吹き出しに畳む部品は DR-0062 §12 (「解決済みのスレッドの吹き出しの畳み」、P36、P37) にある。この DR は、その部品を既読の項目にも使う。

### 読んで分かった前提

- **応答の吹き出し**: TL のエージェントの応答の吹き出しは、境界の分類 (webui の `transcript-model.ts` の `classifyBoundaryLine`) が `assistant-response` とするメッセージ (text を持つ assistant の行で、keep-alive の応答と `nothing_to_reply` を除く) の項目。項目の包み (`ItemRawToggle`) は、そのメッセージの uuid を TL の位置 (`data-timeline-uuid`) として持つ。コメントのメッセージのアンカー (DR-0062 §2) とブックマーク ([DR-0058](./DR-0058-timeline-bookmarks.md) §2) が指すのも同じ uuid
- **say の既読** ([DR-0045](./DR-0045-say-speaks-in-tool-shown-from-transcript.md) §7、daemon の `say-unread.ts`): キーは `say` の呼び出しの tool_use の id。daemon は既読の id (sid ごと) と時刻 `since` を全セッション 1 ファイルの `say-read.json` に持ち、未読 (見つけた say のうち、既読に無く `since` 以後のもの) を `ev:"say_unread"` で user role の全タブに配る。webui は未読の列だけを受け、そこに無い say を既読として描く (`useSayRead`)。op `say_read { ids }` は既読にするだけで、外す op は無い。live でないセッションの既読の id は daemon の起動の時に落とす (`pruneNotificationState`)。subagent / teammate の say は親の transcript に行が無く、tool_use の id で親の TL に合流する ([DR-0050](./DR-0050-timeline-notification-badges.md) §10)
- **許可依頼の既読** ([DR-0040](./DR-0040-permit-request-tool.md) §4、§5、§7、daemon の `permit-state.ts`): キーは `permit` の呼び出しの tool_use の id。`permit-state.json` に `read` / `granted` と項目ごとの印を持ち、未読を `ev:"permit_state"` の `unread` で配る。未読は「既読に無く、`since` 以後で、項目が全部済んではいないもの」で、「既読」「まとめて許可」のほか、項目が全部済んだ時にも未読から外れる。`read` と `granted` は一度立てたら戻さない
- **コメントの記録の置き場と配り方** (DR-0062 §7〜§10、daemon の `comments.ts`): セッションごとの追記のファイル `<stateDir>/sessions/<sid>.comments.jsonl` に、コメントの記録とスレッドの状態 (`ThreadStateSchema`) を 1 行 1 つで持ち、同じキーの後の行が前の行に勝つ。書き込みは sid ごとの記録の列で直列にし、人の操作の行が書けなければ `state_not_writable` で断る。そのセッションを見ているタブ (`session_status_subscribe`) に、購読の始まりの `ev:"comments"` と変化ごとの ev を配る。寿命は `sessions/` の 30 日の掃除
- **ブックマークの置き場と配り方** (DR-0058 §4、daemon の `bookmarks.ts`): セッションごとの uuid の列を全セッション 1 ファイルの `bookmarks.json` に持ち、変わるたびに全セッション分を user role の全タブに `ev:"bookmarks"` で送る。終わったセッションの分を消す時機は決まっていない (DR-0058 U3)
- **fold の開閉の持ち方** (webui の `fold-open-store.ts`、`useFoldOpen`): TL ごとの store がキーごとの開閉をメモリに持ち、位置への着地が閉じた fold をキーで開く (`openFoldsAt`)。fold の本文は開くまで描かず、一度描いた後は閉じても描いたまま保つ

## 目的

読み終えた項目に人が印を付けて、TL の中で場所を取らないようにし、まだ読んでいない返信と後で要る返信を見つけやすくする。印を付けた項目は無くならない: 何がそこにあったかが 1 行で分かり、いつでも元の形で読み直せる。印は、どのデバイスで付けても、同じセッションを見ている全ての webui で同じに見える。

印が変えないもの (手順には現れないが保つもの):

- 印の付け外しは、エージェントにもセッションにも何も送らない。transcript も変えない
- 印を付けた項目は、TL の位置・ブックマーク・コメント・検索の対象のまま

増やしたくないもの:

- **TL で常に目に入る物の数**: 足すのは、応答の吹き出しのボタン 1 つと、畳んだ項目 1 つにつき 1 行だけの吹き出し 1 つ。件数の表示・まとめの行・ツールバーの印・フィルタを足さない
- **人の操作の手数**: 既読にするのも開くのも 1 回押すだけで、確認を挟まない
- **daemon が持つ状態の種類とファイル**: 新しいファイル・購読・読み戻しの経路を作らず、コメントの記録の仕組みに行の種類を 1 つ足す
- **「既読」の語の意味**: 「既読」のボタンは、どの項目でも同じ見え方 (1 行だけの吹き出しに畳む) を起こす。同じ吹き出しに「既読」を 2 つ置かない
- **TL の描画の経路と項目の種類**: 畳んだ項目のために TL を別に描かず、項目の並び・位置・fold の切れ目を既読の付け外しで変えない

## 前提

DR-0062 §12 の畳みの部品 (DR-0062 の実装の段階 6) があること。無い間は、印は付くが見え方が変わらないので、この DR の実装はその後にする。

## Decision

### 1. 用語

| 語 | 意味 |
|---|---|
| 応答の既読 | 人がエージェントの応答の吹き出しに付ける印。この DR が足す状態 |
| say / 許可依頼の既読 | 未読でないこと。今ある状態 (DR-0045 §7、DR-0040 §4) で、この DR は持ち方を変えない |
| 畳む | 項目を、中身が 1 行だけの吹き出しで出すこと (DR-0062 §12) |
| 開く | 畳んだ項目を、印を変えずに元の吹き出しで出すこと。その画面の中だけの状態 |

### 2. 既読を付けられる項目と、そのキー

- 応答の既読を付けられるのは、セッション自身の TL の、メインの会話のエージェントの応答の吹き出し (境界の分類が `assistant-response` のメッセージで、読み込んだ範囲 (窓) の中にあるもの)。「返信」(DR-0062 §3) を持つ応答の吹き出しと同じ組
- **キーはその吹き出しの行 (メッセージ) の uuid。状態は sid ごとの既読の uuid の集合** (kawaz 2026-11-26)
- 1 つの応答が text の行ごとに複数の吹き出しになる時は、吹き出しごとに付ける
- fork したセッションには継がない
- say と許可依頼は、今の既読 (キーは tool_use の id) をそのまま使い、この集合に入れない (§3)

### 3. say と許可依頼の既読との関係

**状態は別のまま持ち、見え方だけを揃える** (統括の判断。kawaz 2026-11-26: 融合するか別扱いにするかは任せる)。say と許可依頼には新しい状態もボタンも足さず、今の「未読でない」を畳む条件にする。

2 つの既読を 1 つの集合にしないのは、それぞれの性質が別の要求から来ていて、同時には満たせないため:

| | 応答の既読 | say / 許可依頼の既読 |
|---|---|---|
| 何の印か | 読み終えたので畳んでよい | 呼びかけ・依頼に手を付けた (未読の数から外す) |
| 印の無い時 | 何でもない (数えない) | 未読 (Sessions の行と TL のツールバーの 🔔 🔐 に数える) |
| キー | メッセージの uuid | tool_use の id (親の transcript に行の無い subagent / teammate の say と、窓の外の say・依頼も指す) |
| 外す | できる | できない (許可依頼は、項目の印を外すと未読に戻ることがある) |
| 配る相手 | そのセッションを見ているタブ | user role の全タブ (Sessions の一覧のバッジに要る) |
| 寿命 | セッションの記録と同じ (最後の書き込みから 30 日) | live でないセッションの分は daemon の起動の時に落とす |

印の無い時の意味が逆なので、1 つの集合に入れると、応答が全部「未読」として 🔔 に数えられるか、say の未読が数えられなくなる。

一方、同じ「既読」の語のボタンが、応答では畳み、say では畳まないと、語の意味が項目で変わる (目的の「増やしたくないもの」)。そこで見え方を 1 つにする:

| 項目 | 畳む条件 | 状態の源 (今あるもの) |
|---|---|---|
| say (メインの会話のものと、親の TL に合流した subagent / teammate のもの) | 未読でない | `ev:"say_unread"` |
| 許可依頼 | 未読でない | `ev:"permit_state"` の `unread` |

- 既読にする操作は今のまま (say の「既読」、許可依頼の「既読」と「まとめて許可」、🔔 / 🔐 のフィルタの「全て既読」)。押すと未読の数から外れ、TL ではその項目が 1 行だけの吹き出しに畳まれる
- 開いた吹き出しは今のまま (say は 🔕 と「既読」の字、許可依頼は 🔓 と「既読済み」)
- `since` より前の say と許可依頼は未読でないので、畳んで出る
- 既読の管理の外の say (agent の TL の say) と PushNotification の 🔔 は畳まない (既読を持たない)
- **say と許可依頼の既読を外す操作は足さない** (統括の判断): `say_read` / `permit_read` は既読にするだけのまま (DR-0040 §4 の「一度立てたら戻さない」も変えない)。外せると未読の数 (Sessions の行と TL の 🔔 🔐) が増え、未読が「まだ手を付けていない」と「読み直したいので広げておく」の 2 つの意味を持つ。読み直すだけなら、畳んだ吹き出しを押して開けば足りる。応答の既読と違い、畳んだ say・許可依頼を開いた吹き出しには外すボタンが無い
- **許可依頼は、人が「既読」を押さずに未読から外れた時にも畳む** (統括の判断): 項目が全部済んだ時と、「まとめて許可」で許可済みになった時 (DR-0040 §4)。畳む条件を「未読でない」の 1 つに保ち、済んだ依頼の大きい吹き出しを TL に残さない

### 4. 状態の置き場と配り方

**コメントの記録の仕組み (DR-0062 §7〜§10) に、行の種類を 1 つ足す** (統括の判断)。

- **記録** (`ReadMarkSchema`): `{ kind: "read", session_id, uuid, read }`。`uuid` は応答のメッセージの uuid、`read` は既読か (外した時は `false` の行を足す)。時刻は持たない (読む場所が無い。op の時刻は daemon.log に残る)
- **保存**: `<stateDir>/sessions/<sid>.comments.jsonl` に 1 行で追記する。同じ uuid の後の行が前の行に勝つ (DR-0062 §8 の読み方のまま)。書き込みは sid ごとの記録の列を通し、書けなければ `state_not_writable` で断って、メモリも配りも変えない (人の操作の行の扱い、DR-0062 §8)。寿命は `sessions/` の掃除 (最後の書き込みから 30 日)
- **op** `read_mark_set { session_id, uuid, read }` → `{ ok: true }` (user role だけ。session role は `bad_request`)。`session_id` の検査と `session_not_found` は、DR-0062 §9 のコメントの op と同じ。`uuid` が UUID の形でなければ `invalid_args`。同じ状態への設定は何も書かず、送らない
  - daemon は、その uuid のメッセージが応答かどうかを見ない (統括の判断)。どれが応答の吹き出しかは webui の境界の分類が決めるもので、daemon に同じ判定を持たせない (判定を 2 か所に持たない、DR-0058 §11)。印が見え方に効くのは、webui が畳める項目として描くメッセージだけ
  - 見ていた版の検査は持たない。最後の操作が勝つ
- **配り方**: `session_status_subscribe` の購読 (DR-0062 P28) に載せる
  - 購読の始まりの `ev:"comments"` に `read_marks` (既読の記録の列。`read` が `false` のものは含めない) を足す
  - 変わるたびに `ev:"read_mark" { mark }` を送る。webui は uuid で置き換える (`read` が `false` なら外す)
- **非楽観**: ボタンを押しても、daemon の push が来るまで見え方を変えない。断られた理由はボタンの下の段に出す (解決のボタンと同じ、DR-0062 P14)
- daemon.log に op ごとに 1 行 (sid、uuid、`read`)

Design rationale: `bookmarks.json` と同じ「全セッション 1 ファイルで、変わるたびに全セッション分を全タブへ送る」形にしない。形は同じ uuid の集合だが、既読は読み終えた応答ごとに押すもので、ブックマークよりずっと多く、頻繁に変わる。1 回押すたびに全セッション分を書き直して全タブへ送ることになり、終わったセッションの分を消す時機も別に決めることになる (DR-0058 U3)。セッションごとの追記の記録なら、書くのは 1 行、配る相手はそのセッションを見ているタブだけで、掃除は `sessions/` の 30 日に乗る。コメントの記録のファイルに載せるのは、寿命・書き込みの列・購読が同じで、TL の畳みのもう 1 つの源 (スレッドの解決済み) が既にそこにあるため。

### 5. TL の見え方

DR-0062 §12 の「解決済みのスレッドの吹き出しの畳み」と同じ部品・同じ決まり (P36、P37) で、次の項目を畳む。畳んだ形は、1 行だけのメッセージの吹き出しに見える形 (その項目の吹き出しと同じ枠・同じ地の色・同じ側に、下の 1 行だけが入り、行末で切る)。項目ごとに違うのは、畳む条件と中身の字だけ。

| 項目 | 畳む条件 | 畳んだ吹き出しの中身 | 開閉のキー |
|---|---|---|---|
| エージェントの応答の吹き出し | 既読 (§2) | `（✅ 既読: <本文の冒頭>…）` | メッセージの uuid |
| say | 未読でない (§3) | `（✅ 既読: <読み上げる文の冒頭>…）` | tool_use の id |
| 許可依頼 | 未読でない (§3) | `（✅ 既読: <止められた行動の冒頭>…）` | tool_use の id |
| コメントのスレッドの項目 | スレッドが解決済み (DR-0062 §6) | `（✅ 解決済み: <本文の冒頭>…）` | cid |

- 畳んだ吹き出しを押すと、1 行から元の高さへ縦に伸びて元の吹き出しに戻り、印は変わらない (kawaz 2026-11-26)。開いたかは項目ごとに、その画面の中だけで持つ (統括案、kawaz の異論なし)
- 畳むのはフィルタの無い TL だけで、どのフィルタの中でも元の吹き出しで出す (DR-0062 P36)。フィルタの中で既読にした項目は、フィルタを外した時に畳んだ形で出る
- 既読にした時は、開く時の逆の動きで、元の高さから 1 行だけの吹き出しへ縮む。別のデバイスでの既読の知らせの時も同じ。既読を外すと元の吹き出しに戻り、開いていたことも忘れる (付け直すと畳んだ形から始まる) (DR-0062 P37)
- **どの印で畳むかは 1 つの純関数で決める** (統括の判断): webui の純関数が、項目の種類と上の 4 つの状態から「畳むか」と「畳んだ吹き出しの中身」を返し、項目の包みはそれだけを読む。項目の種類ごとに畳みの判定を別々に書かない
- 既読にした応答に後からコメントが付いても、既読は外さない (統括案、kawaz の異論なし)。項目の 💬 の印は畳んだ吹き出しにも出る (DR-0062 P37) ので、コメントが付いたことは分かる
- agent の TL (subagent / teammate) では畳まず、応答の既読のボタンも出さない (§2)

### 6. 応答の既読のボタン

- 字は、既読でない時「✔️既読」(押すと既読)、既読の時「✅既読」(押すと外す)。解決のボタン (DR-0062 §6) と同じ部品で、2 つを `StackedLabels` で同じ升目に重ねて幅を変えず、既読の間は枠を accent にする。字は CSS で出し (本文の選択とコピーに入れない)、読み上げる名前は「既読にする」「既読を外す」、押されているかは `aria-pressed`
- 置き場は吹き出しの右下: 本文の一番下の「返信」の行の、「返信」のすぐ左 (解決のボタンの置き場と同じ、DR-0062 P14。応答の吹き出しはスレッドの項目でないので、2 つが並ぶことは無い)。hover を待たず常に出す
- 押すと `read_mark_set` を送る。確認は挟まない
- say と許可依頼の「既読」のボタンは今のまま (字も置き場も変えない)

### 7. やらないこと

| やらないこと | 理由 |
|---|---|
| ccmsg で届いた文・teammate のメッセージ・人の発言・tool の項目に既読を付ける | kawaz の依頼はエージェントの応答 (と say・許可依頼)。対象を広げると、常に目に入るボタンが項目の数だけ増える (目的の「増やしたくないもの」) |
| 「ここまで全部既読」などのまとめての操作 | 入れない (kawaz 2026-11-26) |
| 続く畳んだ吹き出しを 1 つにまとめる、既読の件数を出す、既読だけ・未読だけのフィルタ | TL で常に目に入る物と見え方の種類を増やさない (目的) |
| エージェントが既読を付ける・既読を知る | 既読は読んだ人の印で、会話に何も送らない (目的) |

**後から対象を足せるか**: 畳みは項目の種類を問わない部品で、記録はメッセージの uuid だけを持ち、daemon はメッセージの種類を見ない (§4)。webui が畳める項目として描いて既読のボタンを置けば、他の項目にも足せる。1 つのメッセージが複数の項目に描かれるもの (複数のメッセージを運ぶ ccmsg の行) は、足す時にその中の 1 つの指し方を決める。

### 8. 既存の DR との関係

- **[DR-0062](./DR-0062-comments.md)**: §12 の畳みの部品と P36・P37 をそのまま使う。この DR を受理したら、DR-0062 の §7 (記録の種類)・§8 (ファイルが持つもの)・§10 (`ev:"comments"` の `read_marks` と `ev:"read_mark"`) に行の種類を足す。開いた項目を畳み直す操作を持たないこと (DR-0062 §12) は、既読の項目も同じ
- **[DR-0045](./DR-0045-say-speaks-in-tool-shown-from-transcript.md) §7 / [DR-0040](./DR-0040-permit-request-tool.md) §4・§7 / [DR-0027](./DR-0027-tl-ccmsg-canonical-lookup.md) §6.3**: say と許可依頼の既読の持ち方・op・ボタンは変えない。足すのは、未読でないものを TL で畳むことだけ
- **[DR-0050](./DR-0050-timeline-notification-badges.md)**: 🔔 / 🔐 のフィルタの中では畳まないので、フィルタの見え方と「全て既読」は今のまま。数も変わらない
- **[DR-0058](./DR-0058-timeline-bookmarks.md)**: ブックマークと同じくメッセージの uuid を指すが、置き場と配り方は別 (§4 の Design rationale)。⭐ は畳んだ吹き出しにも出る
- **[DR-0061](./DR-0061-no-clear-handling.md)**: `/clear` で sid が替わった時の扱いは考えない

## 実装の時に確かめること

- live でないセッションの TL で、daemon の再起動の後に say と許可依頼がどう出るか。実装を読んだ限りでは、起動の時に既読の id が落ち (`pruneNotificationState`)、`since` 以後の say と依頼は未読に戻って畳まれずに出る。実機では確かめていない
- 許可依頼の操作の直後に畳まれる時の見え方 (§3) を、実ブラウザで見る。最後の項目の「! で実行」や「まとめて許可」を押した直後に、その吹き出しが 1 行だけの吹き出しに縮み、押した結果 (「実行済み」「コピーしました」) をその場で見られない (コマンドの出力は TL の `!` のカードに、許可の文は入力欄に出る)。困るなら、その画面で操作した依頼を、その画面の間だけ元の吹き出しのまま残す決まりを足す

## Alternatives Considered

| 案 | 採らない理由 |
|---|---|
| 既読を `bookmarks.json` と同じ形 (全セッション 1 ファイル、変わるたびに全セッション分を全タブへ) で持つ | §4 の Design rationale。1 回押すたびに全セッション分を書き直して送ることになり、終わったセッションの分を消す時機も別に要る |
| 応答の既読を `say-read.json` / `permit-state.json` に入れて、1 つの既読の集合にする | §3。印の無い時の意味・キー・配る相手・寿命が違い、同時に満たせない |
| say と許可依頼にも、通知の未読とは別の「畳むための既読」を uuid で持たせる | 同じ吹き出しに「既読」が 2 つになり、同じ語が 2 つの状態を指す |
| say と許可依頼は畳まない | 同じ「既読」のボタンが、応答では畳み、say では畳まないことになる |
| 既読だけのファイル (`<sid>.read.jsonl`) と専用の購読を作る | 読み戻し・書き込みの列・書けない時の扱い・購読の始まりの push をもう 1 組持つことになる。コメントの記録の仕組みがそのまま使える |
| 既読を webui の localStorage に持つ | 別のデバイスで見えない |
| 既読を「このメッセージまで読んだ」の位置 1 つで持つ | 要らない応答を選んで畳み、要る応答を残すことができない |
| 既読の項目を TL から消す (何も出さない) | 何がそこにあったかが分からなくなり、読み直す口と外す口が無くなる (kawaz 2026-11-26) |
| 既読の応答を前後の fold (「N items」) の中に入れる | DR-0062 の Alternatives の「畳んだ項目を前後の fold の中に入れる」と同じ。項目が境界でなくなり、既読の付け外しのたびに前後の fold が作り直される |
| 開いたかを daemon か localStorage に持つ | 読み返すための一時の見え方で、別のデバイスや次に開いた時まで開いたままだと、畳んだ意味が無い |

## Consequences

- protocol: `ReadMarkSchema`、op `read_mark_set`、`ev:"read_mark"`、`ev:"comments"` の `read_marks`、`<sid>.comments.jsonl` の行の種類 `read`。読むのは webui だけなので PROTOCOL_VERSION は動かさない (DR-0058 §4 と同じ)
- daemon: コメントの記録の読み戻し・メモリ・書き込みに既読の行を足し、op `read_mark_set` と購読への配りを足す。新しいファイル・購読・定期の処理は足さない
- webui: 応答の吹き出しの既読のボタン、既読の集合の store、畳む条件を決める純関数、say と許可依頼の畳み
- 既読を多く付けたセッションの TL は、読み込み直した時に畳んだ項目の本文を描かないので、その分軽くなる (DR-0062 P37)
- `<sid>.comments.jsonl` に、既読の付け外しのたびに 1 行 (約 120 byte) が足される。書き直して縮めることはしない (人の操作の回数で、ファイルは 30 日の掃除で消える)
- 応答の既読は、最後の書き込みから 30 日で消える (コメントと同じ)。say と許可依頼の既読は、今のとおり live でないセッションの分が daemon の起動の時に落ちるので、終わったセッションの TL では、応答は畳まれたまま、say と許可依頼は畳まれずに出ることがある
- 「持たない」ことを壊す変更を止める試験の観点:
  - user role 以外の `read_mark_set` は断り、何も保存しない。UUID の形でない `uuid` は断る
  - 既読の付け外しは、セッションに何も送らない (`prompt.send` を呼ばない)。transcript を書かない
  - 応答の既読は say と許可依頼の未読の数を変えず、`say_read` / `permit_read` は応答の既読を変えない
  - 同じ状態への設定は行を書かず、何も送らない。`read` が `false` の後の行が前の既読に勝つ
  - `ev:"read_mark"` は、そのセッションを Files / Status / Timeline のどのタブで見ている接続にも届き、別の接続 (別のデバイス) にも届く。購読していない接続には届かない。購読の始まりの `ev:"comments"` が既読の記録を持つ
  - daemon の再起動の後も、ファイルから読んだ既読が配られる
  - 既読の応答・未読でない say・未読でない許可依頼は、フィルタの無い TL で中身が 1 行だけの吹き出しになり、どのフィルタの中でも元の吹き出しで出る。既読の管理の外の say と PushNotification は畳まれない
  - 畳んだ吹き出しを押して開いても、op を 1 つも送らない
  - 既読の付け外しの前後で、TL の項目の数・位置 (`data-timeline-uuid`)・fold の切れ目が変わらない
  - 応答の吹き出しに「既読」のボタンは 1 つで、say と許可依頼の吹き出しに 2 つ目の「既読」が出ない
