# DR-0061: `/clear` で sid が替わった時の扱いを設計の責務にしない

- Status: Accepted (2026-11-22、kawaz 指示) — N/A (設計の進め方の決まり)
- Date: 2026-11-22

## Context

Claude Code の `/clear` は、同じプロセスのまま会話を捨て、新しい session id で続ける。ccmsg の機能はセッションごとに状態を持つもの (btw の記録、添付の番号、未送信のコメント等) が多く、設計のたびに「`/clear` で sid が替わった時に何を引き継ぐか」が論点に挙がる。kawaz の指示の要点:

> 少なくとも ccmsg プロジェクトでは /clear 時の備えは気にしなくて良い。そこはユーザ責務として、今後も担保をいちいち考えなくて良いこととして良い。新規セッションを立て直すのが簡単なので困らない。

kawaz は `/clear` を使わず、Status タブから新しいセッションを起こす。

## Decision

- ccmsg の機能の設計では、`/clear` で sid が替わった場合の担保 (状態の引き継ぎ、番号の振り直し、古い sid の記録を新しい sid の画面に見せる等) を考えない。sid ごとの状態は、その sid のものとして扱い、それ以上の対応はしない
- DR・設計文書・issue に `/clear` の時の節を書かない。`/clear` の扱いが論点に挙がったら、この DR を指して閉じる
- `/clear` を使った結果の不便は使う人の責務とする

compact (同じ sid のまま context が畳まれる) はこの DR の対象ではない。compact の後も働くこと (例: エージェントへの指示を tool の説明文に置く) は、引き続き設計で考える。

## Consequences

- sid ごとの状態を持つ機能の設計から、sid の替わり目の論点が消える
- `/clear` を使うと、その前の sid の btw の記録・コメント等は新しい sid の画面に出ない
