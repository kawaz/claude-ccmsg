# DR-0022: In-view キーワード検索 (Timeline の 🔍 のフィルタ / agent の TL とファイルビューアの検索バー)

Status: Accepted (kawaz が仕様を直接指定。§2.1 のクエリ AND/OR 割当は kawaz 指定が正本。§2.2 の 🔍 のフィルタは kawaz の方針 (2026-11-21) を元に統括が決定) — ✅ 実装済み (`SearchForm`、`TimelineFilter` の `search`、`useInViewSearch` の `hitOffsets` / `copySearchCtx`、`matchedFoldRows`、`.tl-lines[data-filter="search"]`)
Date: 2026-07-17 (§2.2: 2026-11-21)
Sponsor: kawaz

## 1. 背景

表示中の Timeline / ファイルビューア内をキーワード検索したい (kawaz)。ブラウザ標準のCmd+F は standalone PWA では使えず、fold された TL 構造にも効かない。

セッションの TL では、検索をツールバーの入力欄と ↑↓ でなく、🔔 / 🔐 / ⭐ / 👤 と同じフィルタにする (kawaz 2026-11-21: 「🔍 も場所だけ取ってるけどこれもフィルタにした方が使い勝手良い」「ツールバーの中でクエリ入れてるとこを、フィルタ画面内に専用フォームを置く方が UI もよく出来そう」「ツールバーにキーワード一覧が並ぶ必要はない。フィルタに切り替えればそこで見れる。ハイライトは今まで通りで良い」)。

## 2. 仕様

### 2.1 クエリと照合 (どの面も共通)

- **[Aa] / [.*] の 2 トグルボタン**: それぞれ case sensitive / regex
- クエリはマルチライン可。通常検索は**行内の空白区切りワードを AND、改行区切りを OR** とする (= 行ごとの AND グループを OR で束ねる)。ダブルクオートで囲んだ句は 1 ワードとして扱い、句内の連続空白は `\s+` マッチに正規化する
- regex 検索は行内を分割せず、各行を独立した正規表現として改行区切り OR にする。空行だけを無視し、各行の空白は trim しない
- 検索語は**各ワードを別チップで一列表示**し、TL / コードでは**行毎に別色**でハイライトし、同じ行の AND ワードは同色にする
- TL の検索対象のトグル: 👤 (ユーザの発言) / 🤖 (AI の応答と thinking) / 💬 (ccmsg 経由のメッセージ)
- TL の検索語と照合のモードはセッションごとに store (`timelineSearch`) に持ち、既定は `👺` の印の正規表現。Session Search から TL を開くと、その検索語を引き継いで TL にハイライトを出す (フィルタには入らない)

### 2.2 セッションの TL: 🔍 のフィルタ

- **ツールバー**: 🔔 🔐 ⭐ 👤 の右に 🔍 を同じ正方形のバッジで置く (`TOOLBAR_BADGE_KINDS`)。数は出さない。押すと `?filter=search` ([webui-url-grammar](../design/webui-url-grammar.md)) の 🔍 のフィルタに入り、選択中の 🔍 を押すと今の位置のまま外れる (他のフィルタと同じ、DR-0050 §3・§4)。ツールバーには入力欄・検索語の札・一致の数・↑↓ を置かない
- **フォーム** (`SearchForm`、`.tl-search-form`): フィルタの画面の上 (「過去分を上に読み込む」の場所の下、行の列の上) に、TL の幅いっぱいの入力欄、[Aa] [.*]、👤 🤖 💬、一致した項目の数 (「一致 N 項目 (読み込み済みの範囲)」)、検索語の札、「過去分を読む」を置く。フィルタの無い間は同じ要素を `hidden` で隠す (フィルタの切り替えで作り直さない)。検索語は URL に載せず、store のまま。位置を選ばずに 🔍 のフィルタに入った時は、他のフィルタ (末尾から) と違い上端から見せる (フォームから使うため、`useFilterScroll`)
- **並ぶもの**: 読み込み済みの範囲 (窓) の中で、検索語に一致した unit の行の項目。境界の項目 (発言、応答、ccmsg 等) はその場に残し (`data-search-hit`)、fold の中の行 (thinking、途中の応答、fold の中の ccmsg) は ⭐ の fold の行と同じく fold の外に写しを描いて時刻の位置に並べる (`matchedFoldRows`、`data-filter-only="search"`)。写しの中の一致も同じ色で塗る (`copySearchCtx`)。日付の帯は 🔍 の見え方の並びで決める
- **見せ方**: 他のフィルタと同じ (DR-0050 §4・§5・§6、DR-0058 §6)。本文は 8lh で抑え、収まらない項目のクリックは広げるだけ、広げた項目・収まる項目のクリックは `seek=true` 付きでその行の位置へ replace で移り、短い smooth で着地する (fold の中の行は fold を開いて着地、DR-0058 §2)。末尾に「TL に戻る」。検索語が無ければ「検索語を入れると、一致した項目だけが並びます」、一致が無ければ「読み込み済みの範囲に一致はありません」
- **TL に移った後**: 検索語は store に残るので、TL の中のハイライト (CSS Custom Highlight) は今のまま残る。消えるのは検索語を空にした時
- **窓の外**: 自動では読まない。フォームの「過去分を読む」を押すと、TL の「過去分を上に読み込む」と同じ読み込み (`loadOlder`、TL と同じ窓に 1 ページ足す) をし、読んだ範囲の一致が一覧に加わる。読んだ行はフィルタを外した TL にもそのまま残る。押した後は TL の最上部に寄せ (「過去分を下に読み込む」と同じ寄せ方)、足された一致が読み手の目の前に来るようにする。transcript の先頭まで読み込み済みならボタンを出さない。TL の「過去分を上に読み込む」「過去分を下に読み込む」はどのフィルタの間も出さない (DR-0050 §5)
- **📁 (閉じた fold の中も数える) は使わない**: 一覧は閉じた fold の中の一致も写しで並べるので、一覧に何が並ぶかは transcript と検索語だけで決まる。TL の中のハイライトは、描かれた所に塗る今のまま

Design rationale: 🔔 / 🔐 / ⭐ / 👤 のフィルタは窓の外の項目を daemon から全部取るが、🔍 は daemon に聞かず窓の中で判定する。検索は描かれる本文 (markdown の後の字、届いた訳、ccmsg の本文) を検索語・大文字小文字・正規表現・検索対象のトグルで照合するもので、同じ結果を出せるのは webui の描画の側だけ (daemon の `session_search` はセッションを探す検索で、1 セッションの中の項目を同じ規則では返さない)。窓の外は人が「過去分を読む」で窓を広げて探す。

### 2.3 agent の TL とファイルビューア: 検索バー

agent の TL はフィルタを読まない (DR-0050 §4) ので、ツールバーに今の検索バー (`SearchBar`) を置く。ファイルビューアも同じ。

- 🔍 ボタン → 押すとクエリ入力が出る。入力欄外クリックで入力欄を閉じ、チップを一列に並べる
- 表示イメージ: 検索なし `🔍`、検索あり `🔍 foo bar [1/20]↑↓`
- `[1/20]` = 現在インデックス / 総マッチ数。↑↓ で現在インデックスを動かし、その要素までスクロールする (閉じた fold の中なら開く)。押した結果の移動なので短い smooth で動かす (DR-0056)
- **ハイライトをビューア上でクリック** → `1/20` の現在値がその要素のインデックスに更新 (この数字変化ではスクロールしない。スクロールを伴う数字変化は ↑↓ ボタンのみ)
- ↑↓ のインデックスは **1 と最大値を越えたらループ**
- agent の TL は 📁 で、閉じた fold の中の一致を `[N/M]` に数えるかを切り替える

### 2.4 セッションの TL で無くなったものと、代わりの操作

| 無くなったもの | 代わり |
|---|---|
| ツールバーの検索語の札と `[N/M]` | 🔍 のフィルタのフォームに札と「一致 N 項目」 |
| ↑↓ で TL の中の一致を順に飛ぶ (端で反対側へ回る、閉じた fold を開いて飛ぶ) | 🔍 のフィルタの一覧から項目を選んで TL のその位置へ移る (fold の中の行は fold を開いて着地) |
| 今の一致の強調 (↑↓ で選んだ一致の色) と、ハイライトのクリックで N を合わせる | 一覧で選んだ項目が TL の位置として選択の枠で示される |
| TL を見たまま打ち、その場でハイライトが変わる | フォームで打つと一覧がその場で変わり、TL に戻ればハイライトが残る |
| 📁 の切り替え | 一覧は閉じた fold の中も含めて常に並べる |

## 3. 設計方針

- webui 完結 (daemon 変更なし)。表示済みコンテンツ (TL の読み込み済み範囲 / ビューアの表示ファイル) に対するクライアントサイド検索
- クエリから直列化可能な AND/OR 正規表現構造を作る parser は protocol package の pure 層に置き、in-view 検索と Session Search で共有する。不正 regex は構造内のエラーとして返す
- in-view 固有のマッチ列挙・AND/OR 判定は webui の pure 層に切り出してテスト
- ハイライトは描画済みの字に CSS Custom Highlight の range を置く。ワード色は palette 固定循環
- 🔍 のフィルタは他のフィルタと同じく、TL の DOM を CSS で絞った見方 (DR-0050 §5)。一致の判定は ↑↓ の数え方と同じ unit の一覧 (`useInViewSearch`) を使い、一致した unit の行の offset (`hitOffsets`) で項目を残す

## 4. Phase 分割

| Phase | スコープ |
|---|---|
| Phase 1 | pure 層 (クエリ parse / マッチ列挙 / index 遷移) + ファイルビューア検索 |
| Phase 2 | Timeline 検索 (fold との相互作用込み) |
| Phase 3 | セッションの TL の検索を 🔍 のフィルタにする (§2.2) |
