# DR-0050: TL ヘッダの 🔔🔐 バッジで、未読の say / 許可依頼だけを TL に出すフィルタを URL で切り替える

- Status: Accepted (2026-11-08、kawaz 裁定) — ⬜ 未実装。§9 の未決が残っている
- Date: 2026-11-08

## Context

未読の say ([DR-0045](./DR-0045-say-speaks-in-tool-shown-from-transcript.md) §7) と未読の許可依頼 ([DR-0040](./DR-0040-permit-request-tool.md) §4・§7) は、Sessions 一覧の行の 🔔 / 🔐 と件数で「どのセッションか」までは分かる。そのセッションの TL を開いた後は、バブルが会話の行の間に時刻順で散らばっていて、長い TL では未読のバブルを探してスクロールすることになる。

全セッション横断の一覧 (サイドバーの Notifications 区画) は作らず、セッションの TL の中で見つけて既読にする (kawaz 2026-11-08)。

## Decision

### 1. 目的

未読の say と許可依頼を、そのセッションの TL の中で見つけて既読にできるようにする。見つける操作の前後で、人が触ったバブルの画面上の位置を動かさない。

増やしたくないもの:

- 未読と既読の正本と経路 (daemon が持ち、`ev:"say_unread"` / `ev:"permit_requests"` / `ev:"permit_request"` で全タブに配る今の形のまま。webui 側に別の未読の状態を持たない)
- TL の描画の経路 (フィルタ用に TL を別に描く部品を作らない)
- URL に載らない画面の状態 (フィルタは URL が正本)

### 2. 未読の数の源と既読

- 🔔 の数は store の `unreadSays` のうち `session_id` がそのセッションのもの (Sessions 一覧の `sayUnreadBySid` と同じ数え方)。🔐 の数は store の `permitRequests` のうち `sid` がそのセッションで `read` が無いもの (`permitUnreadBySid`)
- どちらも main thread の分だけ (subagent の say は未読に入らない DR-0045 §7、許可依頼は subagent の TL に出ない DR-0040 §7)
- 既読にする操作は今のまま: say はバブルの「既読」/「N 件すべて既読」(DR-0027 §6.3)、許可依頼は「許可する」(DR-0040 §7)。バッジは数を出してフィルタを切り替えるだけで、押しても既読にしない
- protocol の変更は要らない (数・時刻・セッションは既存の push に揃っている)

### 3. TL ヘッダのバッジ

- セッションの TL のヘッダの一番左に 🔔 と 🔐 をこの順に並べる (置く行は §9 U1)
- そのセッションの未読が say 0・許可依頼 0 ならバッジを出さない。どちらかが 1 以上なら両方を出す
- 数は絵文字の右上に重ねる赤い角丸の枠に白い数字で出す (カウンター)。未読が 0 の方は絵文字だけで、カウンターを出さない。1 件でも数字を出す
- カウンターは CSS だけで重ねる (バッジを `position: relative` の inline 要素にし、カウンターを `position: absolute` で右上に置く)。行の高さと横幅はカウンターの有無で変えない
- 選択中 (§4 のフィルタがその種類) のバッジは選択中の色 (既存の押下状態のトークン) で塗る
- バッジは `<a href>` にする。押すとフィルタの URL へ遷移する。状態は URL が持ち、セッションのタブが link であるのと同じく中クリックで別窓に開ける

```
未読 say 1・許可依頼 1        [🔔¹] [🔐¹]   ← ¹ は右上の赤いカウンター
🔔 を押す (say だけの TL)      [🔔¹]* [🔐¹]  ← * は選択中の色
既読を押す                     [🔔]* [🔐¹]
say がもう 1 回起きる          [🔔¹]* [🔐¹]  ← TL には say が 2 つ (新しい方が下)
🔔 を押し直す (フィルタ解除)    [🔔¹] [🔐¹]
```

### 4. フィルタの URL

Timeline のページ固有 query `filter` で表す ([webui-url-grammar](../design/webui-url-grammar.md) の「ページ固有 query」に 1 行足す):

| キー | 付く path | 意味 |
|---|---|---|
| `filter` | `/s/<sid>/timeline/<position>` | `say` なら say のバブルだけ、`permit` なら許可依頼のバブルだけを出す |

```
/s/<sid>/timeline/head?filter=say
  say のバブルだけを、末尾から見る
/s/<sid>/timeline/<uuid>?filter=say
  say のバブルだけを出し、<uuid> の say を選択している
/s/<sid>/timeline/<uuid>
  上からフィルタを外した形 (選択は残る)
```

path でなく query にした根拠:

- path は「どこを見ているか」で、フィルタの有無で見ている場所 (そのセッションの TL のその位置) は変わらない。フィルタは同じ path の見え方の引数で、Files の `?path=` / `?lines=` と同じ層に当たる
- `/timeline/<segment>` の 4 番目は位置 (`head` かレコードの uuid) と `agent` が使っている。`/timeline/say/head` のように段を足すと、位置の名前空間と衝突するか、全ての位置の URL の形が変わる
- 位置 (path) とフィルタ (query) が直交するので、§6 の「フィルタを外しても選択は残る」が URL の上で query を 1 つ消すだけになる

規則:

- 値は `say` と `permit` だけを読む。それ以外の値と、空の値は「フィルタなし」として扱う (`sb.panel` の未知の値と同じ)
- agent の TL の path (`/timeline/agent/...`) では読まない
- 位置を変える遷移 (項目のクリックでの選択と解除、最下部に来た時の head への戻し、窓の外の位置の head への戻し) は `filter` を引き継ぐ。`timelineHref` がフィルタを受け取り、位置を書き換える全ての呼び出しがそれを通す
- 「フィルタを外す」はバッジの href が今の path から `filter` を除いたものになることで表す。押した側が path を作り直さないので、選択が落ちない

### 5. フィルタ中の TL の描画

- 描画の経路は変えない。TL は今と同じ groups・バブルを全部描き、フィルタは `.tl-lines` に `data-filter` を付けて、該当しない子を CSS の `display: none` で隠す。該当する子は自分の種類を `data-notif="say"` / `data-notif="permit"` で名乗る (say の境界の `ItemRawToggle`、`PermitRequestBubble` の外枠)
- 隠すのは該当しない全ての子: fold group、user / assistant / ccmsg / bash / API error のバブル、fork の境目、応答中の行 (`TurnResponding`)。既読の失敗の 1 行 (`tl-say-error`) は残す
- 隠すだけなので、fold の開閉・翻訳タブ・raw の表示・読み込み済みの markdown と highlight は解除の後もそのまま残り、解除で描き直しが起きない (§6 の位置合わせが測る要素が同じ DOM のまま)
- フィルタ中に該当するバブルが読み込み済みの範囲に 1 つも無い時は、隠した行の代わりに「読み込み済みの範囲に say はありません」(許可依頼なら「許可依頼はありません」) を 1 行出す。older は今と同じ位置に出し続け、押せば遡れる
- 許可依頼は今と同じく記録の時刻で行の間に合流する (DR-0040 §7、`permitSlots`)。読み込み済みの範囲より古い依頼は先頭の枠に入るので、フィルタ中も常に見える
- 末尾追従 (`useStickToBottom`) はフィルタ中も同じに動く。新しい say が届けば末尾に足され、末尾を見ていれば追う

Design rationale: フィルタを「該当するバブルだけを別に描く」形にしない。別に描くと、解除の時に元の TL の DOM を作り直すことになり、§6 の「触ったバブルの位置を保つ」の基準にする要素が描き直しで別物になる。fold の開閉や翻訳の状態も描き直しで落ちる。CSS で隠すだけなら、要素は解除の前後で同じで、測って合わせるだけで済む。

### 6. フィルタの解除とスクロールの位置

フィルタを外した時、選択しているバブル (URL の位置が指すバブル) の画面内の位置 (scroller の上端からの距離) を、外す前と同じに保つ。上下に隠れていた行が戻り、そのバブルを中心に内容が伸びる。そのバブルを画面の外へ出さない、画面の一番上へ寄せ直さない。

- 遷移の直前 (`BEFORE_NAVIGATION_EVENT`、FileViewer の遷移前の位置の取得と同じ口) に、Timeline が選択中のバブルの `getBoundingClientRect().top - scroller.getBoundingClientRect().top` を記録する。戻る / 進むでフィルタが外れる時もこのイベントが先に来る
- フィルタが外れた描画の後 (layout effect) に、同じ要素の今の距離との差だけ `scrollTop` を足す。これを `useScrollHold` の `toElement` の寄せ方として渡し、戻った行の markdown・highlight・画像が後から伸びても同じ距離を保ち続ける (人が自分でスクロールした時に手放す、`useScrollHold` の既存の規則)
- 位置の着地 (`usePositionLanding`) は走らせない。位置 (path) は変わっていないので着地済みのまま
- ブラウザの scroll anchoring (`overflow-anchor`) には頼らない。Safari は 27 まで持たず (useScrollHold.ts の rationale)、持つブラウザでも基準にする要素をブラウザが選ぶので、選択したバブルが基準になるとは限らない。scroll anchoring が先に動いても、差は実際の距離から測るので結果は変わらない

### 7. Sessions 一覧のバッジ

- 行の 🔔 / 🔐 は残す。出すかどうか・カウンターの形は §3 と同じ規則にする (どちらかが 1 以上なら両方、0 の方は絵文字だけ、数は右上のカウンター)。ピン留めの行も同じ
- 行の 🔔 / 🔐 を押すと、そのセッションの TL をその種類のフィルタで開く (`/s/<sid>/timeline/head?filter=say` / `?filter=permit`)。行の他の部分を押した時の「最後に見ていた画面へ」(`/s/<sid>`) とは別の link にする
- 行の link (`session-main-link`) の中に link は入れられないので、バッジは行の link の兄弟の `<a>` にし、見た目の位置 (アイコンと repo 名の間) は CSS で保つ

### 8. テストの観点

- バッジ: 0/0 で出ない、片方だけ 1 以上で両方出る、0 の方にカウンターが無い、1 でも数字が出る、選択中の色が URL の `filter` に従う
- URL: `filter` の往復 (parse → href)、未知の値と空の値が「なし」になる、agent の path で読まない、位置の選択・解除・head への戻しが `filter` を落とさない、バッジの href が「付ける / 外す」になる
- 描画: フィルタ中に該当しない子が隠れ、該当する子が残る、該当が 0 の時の 1 行、解除で DOM の要素が同じまま (描き直されない)
- 位置: 解除の前後で選択したバブルの距離が同じになる `scrollTop` の補正量 (dom test で上下に隠れていた行の高さを与えて確かめる)、補正の後に内容が伸びても距離が保たれる、人のスクロールで手放す
- Sessions: 行のバッジの href がフィルタ付きの TL で、行の link が `/s/<sid>` のまま

### 9. 未決

仕様 (kawaz 2026-11-08) に無く、決めずに残しているもの。各項目の「推し」は起草者の案で、裁定ではない。

| # | 論点 | 推し | 他の案 |
|---|---|---|---|
| U1 | バッジを置く行 | セッションのタブ列 (`Timeline / Files / …`) の左端。Files / Status を見ている間も未読に気づけ、押せば Timeline へ移る | TL のツールバー (`older` / 検索 / 👤 / ⤒⤓) の左端。Timeline のタブでだけ見える |
| U2 | 🔔 と 🔐 を同時に選べるか | 排他。選択中でない方を押すとその種類に切り替わる (`filter` は値 1 つ) | 両方選べる (`filter=say,permit`) |
| U3 | 🔔 のフィルタに PushNotification の 🔔 バブル (既読を持たない) を含めるか | 含める。見た目も役割も「人への呼びかけ」で、say と同じ 🔔 として描いている | say だけ (未読の数の対象と揃える) |
| U4 | フィルタ中に未読が 0/0 になった時 | 選択中のバッジは 0/0 でも残す (押して解除できなくなるため)。解除したら §3 の規則で消える | 0/0 で消し、ヘッダの外に解除の手段を置く |
| U5 | フィルタに入る時の位置 | バッジの href は `/timeline/head?filter=…` (選択を外して末尾から)。仕様の「一番下がスクロール範囲に入る」に合う | 選択中のバブルがその種類なら選択を保ってそこへ着地する |
| U6 | 選択が無い (head) 時にフィルタを外した時の位置 | 末尾を見ていたら末尾のまま。末尾でなければ画面の一番上に見えているバブルを基準に §6 と同じ方法で保つ (「触った要素は動かない」を、触っていない時は見ていた要素に当てる) | 常に末尾へ |
| U7 | 許可依頼のバブルの選択の表し方 | 位置の段に許可依頼の記録の id を名乗らせる (`/timeline/permit:<id>`)。バブルに `data-timeline-uuid` と同じ属性で載せ、§6 は say と同じに動く。daemon の再起動で記録が消えると窓の外と同じく head に戻る | 許可依頼は選択できないままにし、解除の時は U6 の規則で保つ |
| U8 | 読み込み済みの範囲より古い未読の say | フィルタに入った時、未読の say (`say_unread` の `ts`) が読み込み済みの範囲より古ければ、含まれるまで older を自動で読む (先頭に着いたら止める)。未読を見つけられることが目的なので | 自動では読まず、「読み込み済みの範囲より前に未読の say が N 件」の 1 行と older で遡らせる |
| U9 | フィルタ中の TL 内検索と 👤 のナビ | 検索の一致と移動は見えているバブルだけを対象にし、👤 のナビは無効にする (移動先のユーザ発言が隠れているため) | 検索の移動先が隠れていればフィルタを外して移る |
| U10 | フィルタの切り替えの履歴 | push (戻るでフィルタの前に戻れる。サイドバーのパネルの開閉と同じ扱い) | replace (位置の選択と同じ扱い) |
| U11 | `/s/<sid>` の復元 (最後に見ていた画面) に `filter` を含めるか | 含めない (`sb.*` と同じく落とす)。未読を片付ける一時の見え方で、戻った時に TL の大半が隠れていると驚く | 含める |
| U12 | agent の TL のヘッダ | バッジを出さない (そのセッションの main thread の未読で、agent の TL にはその種類のバブルが無いか既読の外) | 出して、押すと親の TL のフィルタへ移る |
| U13 | Sessions の行の規則の読み | §7 のとおり TL と同じ (片方が 1 以上なら両方、1 でも数字)。今は「未読がある方だけ、2 件以上で数字」 | 行は今の規則のまま、カウンターの形だけ揃える |
| U14 | カウンターの桁 | 100 以上は `99+` | 数をそのまま出す |
| U15 | 許可依頼の既読の操作 | DR-0040 のまま「許可する」で既読 (仕様の「既読を押す」は say の話として読む) | 許可依頼にも既読のボタンを足す (DR-0040 §7 の不採用の見直し) |

## Alternatives Considered

| 案 | 採らない理由 |
|---|---|
| 全セッション横断の未読の一覧 (サイドバーの Notifications 区画) | 未読は Sessions の行の 🔔🔐 で「どのセッションか」まで分かっており、要るのはそのセッションの中で見つけること。横断の一覧は SESSIONS と同じ情報の別の並びで、区画と一覧の状態が増える (kawaz 2026-11-08) |
| フィルタを URL に載せず、Timeline の state (store) に持つ | リロード・戻る・リンクの共有で同じ画面にならない ([webui-url-grammar](../design/webui-url-grammar.md) の前提)。Sessions のバッジから「フィルタ付きの TL」へ飛ぶ導線も link で書けなくなる |
| フィルタを path の段にする (`/timeline/say/<position>`) | §4。位置の名前空間と衝突し、フィルタの有無で path が変わって「見ている場所」と「見え方」が混ざる |
| 該当するバブルだけを別のリストに描く | §5 の rationale。解除で DOM が作り直され、選択したバブルを基準にした位置合わせができない |
| 解除の位置合わせを `overflow-anchor` に任せる | §6。Safari で効かず、基準の要素をブラウザが選ぶ |
| バッジを押したら未読を全部既読にする | 既読は「人がその呼びかけ / 依頼を見た」の印で、バッジを押した時点では中身を見ていない。既読の操作はバブルの上に置いたまま (DR-0027 §6.3、DR-0040 §7) |

## Consequences

- TL の検索・👤 のナビ・older・末尾追従は、フィルタ中に隠れた行の上でも動く前提で書かれている。フィルタ中の振る舞いは U9 の裁定で決まり、実装はそれに沿って各 hook に「隠れている要素を対象にしない」条件を足す
- 隠すだけの方式なので、フィルタ中も TL の全ての行は DOM に居続け、描画の重さはフィルタの無い時と変わらない
- 許可依頼の記録は daemon のメモリにあり、再起動で消える (DR-0040 §4)。再起動の後は 🔐 のフィルタに出るものが無くなる。U7 を位置の段で表す案では、その URL は窓の外と同じく head に戻る
- `webui-url-grammar` の「ページ固有 query」に `filter` の行が増える
