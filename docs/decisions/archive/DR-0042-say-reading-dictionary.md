# DR-0042: say は発声の直前に読み上げ辞書 (TSV) で単語を読みに置き換える

- Status: Superseded by [DR-0045](../DR-0045-say-speaks-in-tool-shown-from-transcript.md) §2 / §3
- Date: 2026-10-27

## Context

音声通知 (`say`) は英単語・頭字語の読みがぶれる。実測で `1Password` は「いちぱすわーど」、`daemon` は「ディーマン」、`sidecar` は「シデカー」、`plugin` は「プルージン」と読まれる。これまでは「エージェントがカタカナに直してから渡す」決まりで避けていたが、決まりを読んだセッションしか守れず、新しい単語は毎回初出の扱いで、同じ誤読を各セッションが別々に踏む ([issue](../../issue/archive/2026-10-27-say-reading-dictionary.md))。

音声の経路は 2 つあり、どちらも CLI が発声の binary (`/usr/bin/say`、試験では `CCMSG_SAY_BIN`) を起こす:

- `ccmsg say` (mods の tool `say` も `bin/ccmsg say <text>` を起こす)。daemon には「どのセッションが喋ったか」の記録を送るだけで、session id が無い・daemon が居ない時は記録を飛ばして発声する
- `ccmsg sidecar permit` の「許可を求めています」([DR-0040](../DR-0040-permit-request-tool.md) §6)

## Decision

### 1. 置き換えは発声の直前の 1 か所 (CLI)

- 発声の binary に渡す直前に、本文の単語を辞書の読みに置き換える。2 つの経路は同じ関数 (`spokenArgs`) を通る
- 置き場を daemon にしない。発声は daemon を介さずに起き (daemon が無くても話す)、daemon が受け取るのは記録だけなので、daemon で置き換えると daemon の無い発声に辞書が効かない
- webui の TL に残る say の記録は、エージェントが書いた原文のまま (辞書は聞こえ方の補正で、書かれた内容ではない)

### 2. 一致の規則 (kawaz 2026-10-27)

- 大文字小文字を無視する。置き換えた後は辞書の読みだけが残る
- 単語の両側を `[_\b]` で区切る: 正規表現で `(?<![A-Za-z0-9])word(?![A-Za-z0-9])`。下線・空白・記号・日本語・文字列の端はどれも区切りなので、`_daemon_` と `の daemon で` と `のdaemonで` には当たり、`daemonize` / `mydaemon` / `daemon2` には当たらない
- 同じ位置に複数の語が当たる時は長い方 (辞書の並びによらない)
- 辞書に無い語はそのまま (初出は仕方ない)
- 語の中の正規表現の記号は文字どおりに扱う (`C++`)

### 3. say の引数のどこを置き換えるか

`ccmsg say` は引数を `/usr/bin/say` にその位置のまま渡す (shim の契約)。置き換えるのは say(1) が本文として読む語だけ:

- 値を取るオプション (`-v` `-r` `-o` `-f` `-n` `-a` と `--voice` 等の長い形、`--file-format` 等の音声形式) の値は本文ではないので触らない。`--name=value` と `-vValue` は 1 語で完結する。`--` の後は全部本文。知らない `-x` はフラグとして渡す
- 本文が引数に無く `-f` も無ければ say は標準入力を読む。標準入力が端末でなければ CLI が読み切って置き換えてから渡す。端末の時は say が打った行ごとに話すので、読み切らずにそのまま渡す (置き換えない)
- `-f <file>` の中身は say が読むので置き換えない

### 4. 辞書のファイル

- `<config dir>/say-dictionary.tsv` (`allowed-origins.json` と同じ場所。既定は `${XDG_CONFIG_HOME:-~/.config}/ccmsg/say-dictionary.tsv`、`CCMSG_CONFIG_DIR` があればその下)。面ごとに分けない
- 1 行に `word<TAB>読み`。`#` で始まる行はコメント、空白だけの行は無視。CRLF の `\r` は改行の一部
- 語は空白を含まない 1 語、読みはタブと改行を含まず空白だけでない文字列。タブがちょうど 1 つでない行・語や読みが規則に合わない行は、ファイル名と行番号と理由を 1 行で警告し、その行だけ飛ばす (残りの行は効く)。警告は発声した CLI の標準エラー (`ccmsg say: <file>:<line>: <理由> — line skipped`) に出す。daemon を介さない経路なので daemon.log には書かない
- 同じ語 (大文字小文字を無視) が 2 度あれば後の行が勝つ
- ファイルそのものが読めない (権限・ディレクトリ等) 時は 1 行警告し、同梱の辞書だけで話す。発声は止めない
- 行の形はスキーマで読む ([DR-0038](../DR-0038-json-is-parsed-by-schema.md)。人が手で書くファイルなので JSON でなく TSV にし、行をタブで分けた配列をスキーマに通す)。スキーマと置き換えの関数は `packages/protocol/src/say-dictionary.ts` に置く (純関数。ファイルの読み書きと発声は CLI)

### 5. 初期値

リポに同梱する (`packages/cli/src/say-dictionary.default.tsv`)。辞書は同梱の語にファイルの語を重ねたもの (kawaz 2026-10-27)。

```
1Password	ワンパスワード
daemon	デーモン
sidecar	サイドカー
plugin	プラグイン
OTP	オーティーピー
URL	ユーアールエル
API	エーピーアイ
CI	シーアイ
PR	ピーアール
jj	ジェイジェイ
Kyell	ケイエール
```

- 同梱の行の後にファイルの行を読んだものとして扱う。同じ語 (大文字小文字を無視) はファイルが勝つ (§4 の「後の行が勝つ」)
- ファイルが無ければ同梱の語だけ。ファイルは 1 行足すだけで始められ、同梱を写す必要はない
- 同梱に語が増えれば、ファイルを持つ人にもそのまま入る

### 6. 編集と反映

- 編集はファイルの直編集だけ (kawaz 2026-10-27: パスが分かれば十分)。人もエージェントも同じファイルを書く。パスは README の say の節と skill に書く
- 反映: 発声のたびに CLI がファイルを読む (`ccmsg say` は 1 回ごとのプロセス)。変更は次の発声から効き、監視や mtime の cache による読み直しの仕組みは要らない (daemon の `allowed-origins.json` は常駐プロセスが読むので mtime で読み直すが、ここは読み手が毎回新しい)

### 7. エージェント側の決まり

ccmsg の skill の `say` の節から「英字の略語はカタカナで書く」を外し、英単語や略語はそのまま書く、とする。読みの崩れる語に気づいたら辞書のファイルに 1 行足す、とファイルのパスと書式を添える。rules 側の同じ決まりは利用側で消す。

## Alternatives Considered

- 案 A: エージェントがカタカナに直してから渡す決まりを続ける
  - 不採用理由: 決まりを読んだセッションしか守れず、新しい語の誤読を各セッションが別々に踏む。直した読みが次のセッションに残らない
- 案 B: daemon で置き換える (daemon が辞書を持ち、`say` の op の返事で置き換えた文を返す)
  - 不採用理由: 発声は daemon を介さず、daemon が無い・session id が無い時も起きる (`ccmsg say` は発声のために daemon を起こさない)。その発声に辞書が効かない
- 案 C: 辞書を編集するコマンド (`ccmsg say-dict add|list|remove`) を足す
  - 不採用理由: パスと書式が分かれば直編集で足りる (kawaz 2026-10-27)。コマンドを足すと help と試験の面が増える

## Consequences

- `ccmsg say` の引数は「そのまま渡す」から「その位置のまま渡し、本文の語だけ置き換える」に変わる。PATH の `say` shim 越しでも辞書が効く
- 本文に辞書の語を含む発声は、置き換え後の文が binary に届く (`CCMSG_SAY_BIN` の試験の期待値も置き換え後)
- 同梱の語を読ませたくない時は、ファイルでその語の読みを書き換える (例: 語そのものを読みにする)。同梱の語を消す書式は持たない
