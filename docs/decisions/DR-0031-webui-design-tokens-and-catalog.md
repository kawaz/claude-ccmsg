# DR-0031: webui デザイントークンと自作コンポーネントカタログ

Status: Accepted
Date: 2026-08-12
Sponsor: kawaz r76m76 (2026-07-30)「404と403のデザインがバラバラ。場当たり的にデザインしてる感が強い。デザインシステムやストーリーブックなどを導入したくなる」
関連 issue: `docs/issue/2026-07-30-webui-component-catalog-design-system.md` (要件の正本、本 DR の Accepted をもって close)

## 1. 背景

webui の余白・文字サイズ・エラーページ等の見た目が場当たり的に決まっており、
統一されたデザインシステムを持たない。kawaz の発端指摘は「404 と 403 のデザインが
バラバラ」で、根はコンポーネント側の値がその場でハードコードされていること。

## 2. 決定

以下の 2 案を比較した。

1. **自作カタログページ** — webui 自身に `/catalog` ルートを持たせ、実 CSS・実テーマで
   コンポーネント一覧を描画する
2. **Ladle**
3. **Storybook**

**裁定 = 案 1**。理由:

- webui は Bun バンドル上に構築されており、案 1 はそのバンドルにそのまま乗る
  (ビルド基盤の追加がゼロ)
- 実 CSS / 実テーマで見える。Ladle / Storybook は専用ビルドパイプラインを介するため、
  webui 本体のスタイル変更がカタログに反映されるまでの経路が別に要る
- playwright visual 検証と isolated daemon 検証フロー (`verify` skill) にそのまま乗る。
  カタログ自体を webui の 1 画面として扱えるため、既存の検証手段を流用できる

## 3. デザイントークン

app.css の `:root` に CSS 変数として定義する。

- `--space-1` 〜 `--space-17` (17 段)。既存コンポーネントの余白を実測し、その値を
  そのまま段として採用した。粗い 12 段程度への丸め込みも検討したが、丸め誤差が
  縦方向に積み上がると最大 9.6px のずれが実測された。段数を絞るより実測値を段に
  採用する方を選ぶ
- `--font-size-3xs` 〜 `--font-size-4xl` (10 段)

規約の正本は `docs/design/design-tokens.md`。コンポーネントはこれらのトークンだけを
参照する (例外はそのファイルの例外リストで管理する)。

## 4. カタログ設計原則

- **daemon から何も読まないリテラル表示**にする。カタログ自体が daemon 状態に
  依存しないため、壊れた画面が daemon 起因かレンダリング起因かの切り分けにカタログを
  使える
- **余白・文字サイズの見本は実トークンで描画**する。トークン値がずれた場合はカタログ上で
  即座に見える
- **見本は副作用を持たない**。この方針から `MemberChip` を presentational な表示専用と
  状態を持つ実体に分離した

## 5. 導線

usage 画面のタブ列 (クオータ / 使用量 / カタログ) にカタログタブを追加する。
topbar に独立アイコンを増やさない (kawaz r119m7)。

## 6. 派生する正規化

カタログ整備の過程で以下の重複実装を正規化した。

- **Fold**: `<details>` を用いた折り畳み UI が 6 箇所に個別実装されていたものを
  共通コンポーネントに統合
- **Tabs**: タブ UI が 6 箇所に個別実装されていたものを共通コンポーネントに統合。
  aria 属性を統一し、`disabled` なタブは `selected` として描画しない
- **dead class 除去**: `.tl-bubble-body-user` が参照されていないことを確認し削除

## 7. スコープ外

Phase 2 として据え置く事項は issue 側で個別に起票する。本 DR は Phase 1
(トークン定義 + カタログページ + 導線 + 上記正規化) の裁定のみを扱う。
