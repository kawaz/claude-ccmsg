## Context

TL の項目は時刻 (吹き出しの足の `HH:MM:SS` と相対時間) を持つが、流し読みでは日の境目が分からない。何日も空いたセッションを開くと、どこから別の日の話かを時刻を 1 つずつ読んで探すことになる。終わったセッションの TL の末尾からは、最後のやり取りからどれだけ経ったかも分からない。kawaz の指示 (2026-11-17) の要点:

> webuiのTL上に、日付の区切り部分に目立つ帯(widthwideな文字配置はセンターなボックス？)を挿入してください。2026年11月16日とかで良い。

> アイテム間の日付ズレが1日なら日付のみ

> アイテム間の日付ズレが2日以上なら した側アイテムの上に同じく日付のみのwideバーを置いて。それプラスその上側に前のアイテムからの間日数が分かることを表示するアイテムを挿入する。

> TLの一番下、最新のターンが終わっている場合、最終ターンからの経過時間を表示するアイテムを一つ表示しておく。

続けて帯の表記に曜日と祝日 (「（月）のような感じの曜日も。ついでに祝日なら。更に曜日の横に（月、XXの日）のように祝日の名前も」)、祝日の供給元に holidays-jp の API の指定があった。実物を見た後の指示:

> もう少し日付のピルを大きくして良いです。横のラインももう少し太くして良いし。青ではなくもう少し目立つ色にしても良い。

> ー（日付）ー の日付の左右に ー（↑ 日付 ↓）ー のような矢印を置いてください。前後の日付セパレーターに飛ぶ意味です。それ以上前の日付セパレータがロードしながらでも探す。一番スタートに到達してしまったら一番上にスクロール。↓も同様に次の日付セパレータがなければTLの最新に移動する。

> TLの最終ターンの後に表示するやつは日付セパレータのとこで使ってる表示と同じものを使ってください。

> 9日ぶり（9d3h 空き） このテキストはくどい。空きというのもデザインからわかります。9日（9d3h） とかで良い。`（9d3h）` 部分は色を薄めて良い。3時間（3h20m） のような感じで。

> その日付が今日の場合は黄色ボーダーを付けるなど見た目変化を足す。

## 目的

TL を流し読みする人が、日の境目、何日も空いた所とその長さ、最後のやり取りからの経過を、項目の時刻を読まずに分かる。

増やしたくないもの: 会話の行として数えられるもの (既読、バッジ、検索、選択、位置、末尾追従、行のメニュー・jsonl・fold)。帯は会話の行の間に置く印で、会話の行の振る舞いを 1 つも持たない。

## Decision

### 1. 日付の帯

- TL に並ぶ隣り合う 2 つの項目が違う暦日に始まる時、下 (新しい側) の項目の真上に、TL の幅いっぱいの帯を 1 つ置く。帯は幅いっぱいの太い (3px) 罫の中央に日付の札を置く形で、下の項目の日付を出す。札の文字は TL の本文より大きく太い
- 帯の色は帯だけの色相 (`--hue-day`) から、他の色相と同じ段の表で導く (札は段 11、札の上の文字は段 1、罫は段 8。dark では段の値が入れ替わり、札は明るく文字は暗くなる)。TL の中で他の意味を持つ色 (吹き出し、🔔🔐、エラー、警告、FAB とリンクの accent) と紛れない色相として teal (190) を採った。札の上の文字のコントラストは light 5.4、dark 9.9 (WCAG AA)。比べて採らなかった色: magenta (345) は light で assistant の吹き出しの紫に寄って見え、ink (gray-12) は dark で白い札になり押せる物に見えた
- 狭い幅で祝日の名前が付いて折り返す時は、行の長さを揃える (`text-wrap: balance`)
- 暦日はブラウザのローカルの暦日 (ブラウザの timezone の時計が示す年月日)。24 時間ごとに区切らない: 夏時間の切り替えで 23 時間・25 時間の日も 1 日と数える
- 読み込まれている範囲の最初の項目の上にも、その項目の日付の帯を置く (今見ている所が何日かが分かるように)。過去分を読み込んで先頭が変わったら、帯は新しい先頭の上に移り、元の先頭は上の項目と日が違えば普通の帯を持つ
- 最後の項目の始まりの暦日が今日 (ブラウザのローカルの暦日の今) より前なら、最後の項目の下に今日の帯を置く (今が何日かが TL の末尾で分かるように。次に来る項目が持つはずの帯)。日付の比べ方は項目の上の帯と同じく項目の始まりで、日をまたいで今日まで続いた fold group の下にも置く。最後の項目が今日より後の日 (時計のずれ) なら置かない (日の並びが逆になる)。見方ごとに決める (§6): フィルタの見方の最後のバブルが前の日なら、その見方にも今日の帯が出る。項目の無い見方には出さない
- 末尾の並びは「最後の項目 → 末尾の経過時間 (§4) → 今日の帯 → 応答中の行 → Waiting... の行 ([DR-0059](./DR-0059-timeline-waiting-notice.md)) → 最新のプロンプトへ移動 (§10)」。経過時間は帯の上 (§2 の「空き → 帯」と同じ並び)、応答中の行は今動いている今日のことなので帯の下
- 今日の項目が届いたら、末尾の今日の帯はその項目の上の普通の帯になる。作り直さず同じ要素が項目の上へ動く: 帯は日付で key を持つ (TL 全体の見方に入る帯のうち、その日の最初の帯が `day-<年月日>`、残りは項目の key を足す)。過去分の読み込みで先頭の帯が同じ日の新しい先頭へ移る時も同じ要素が動く
- 今日の帯 (項目の上の帯でも末尾の帯でも) は、札の地と文字を他の帯と同じにして、札の内側に地より明るい同じ色相の縁 (2px、地の明るさに 0.2 を足した色) を引く。縁は inset の影で描き、札の大きさと帯の高さ・並びを変えない。CSS は日付の要素の `aria-current="date"` で縁を付け、支援技術にもこの属性で今日と伝える (aria-label は日付のまま)
- 今日はブラウザのローカルの暦日の今で、TL が相対時間のために持つ時計 (`useNow`、3 分おき) で進む。タブを開いたまま 0 時を越えると、その時計の次の刻み (3 分以内) で今日の印が次の日の帯に移り、末尾の今日の帯が足される
- 表記は `2026年11月16日（月）`。その日が日本の祝日なら `2026年11月23日（月、勤労感謝の日）` のように曜日の後ろに読点で祝日の名前を足す。括弧は全角。日付と曜日は `Intl.DateTimeFormat` (ja-JP) で組み、自前の曜日の表を持たない
- 祝日は帯の暦日 (ブラウザのローカルの暦日) で日本の祝日表を引く。ブラウザの timezone が日本でなくても、日本の日付に直さずにローカルの暦日のまま引く

### 2. 空きの表示

- 上の項目の終わりの暦日から下の項目の始まりの暦日までが 2 日以上の時、帯の上に空きの表示を 1 つ足す。並びは上から「上の項目 → 空き → 帯 → 下の項目」
- 文言は `9日（9d3h）`: 上の項目の終わりから下の項目の始まりまでの時間を、§4 の末尾と同じ数え方で出す (前半は経過のいちばん大きい単位を切り捨てで、括弧の中は `formatDuration` の表記)。暦日の差は空きを出すかどうかの判定にだけ使い、文言には使わない (暦日の差が 2 でも経過が 1d2h なら `1日（1d2h）`)。括弧は前半より弱い色で描く。「ぶり」「空き」の語は出さない (見た目と置き場所で分かる)。支援技術には `前の項目から9日3時間` の文を名前にする
- 見た目は点線の縦の継ぎ目で挟んだ中央寄せの小さな文字 (面を持たず、間が飛んでいることを線の途切れで表す)。主の語 (`9日`) は流し読みで拾えるよう印の文字の 200% の大きさ、括弧の中は印の小さな文字のまま。§4 の末尾の経過時間と同じ部品・同じ CSS (`.tl-elapsed`)。寄せ方だけが違い、末尾は左寄せ (§4)
- 1 日だけ違う時 (夜をまたいだだけ) は帯だけ

### 3. 項目と、その時刻

- 判定は TL に実際に表示される項目の並びに対して行う。表示される項目は `.tl-lines` の直下に描かれる会話の項目で、境界の行 (人の発話、応答、say、許可依頼、ccmsg 等) の吹き出しと fold group、時刻で合流する吹き出し (worker の say、フィルタ中の窓の外の say / 許可依頼)。何も描かない境界 (描く吹き出しが別の所にある ccmsg) は数えない
- fold group は中身が開いていても閉じていても 1 つの項目で、中の行の間には帯を置かない。fold group の始まりは時刻を持つ最初の行、終わりは最後の行。帯の要否と日付は項目の始まりで決め (隣の項目と始まりの暦日が違えば帯)、空きは上の項目の終わりから測る。日をまたいで続いた fold group の次の項目は、新しい日の帯を持つが、空いた日は無いので空きを持たない
- 時刻は各行の `timestamp` (TL の行の `ts`)。時刻を持たない項目 (読めない行だけの fold) は判定で飛ばし、その上下の項目どうしを比べる
- フィルタ (DR-0050 §4) の間は、そのフィルタに残るバブルの並びで決める。フィルタで隠れる行は数えない

### 4. 末尾の最後のターンからの経過時間

- TL が見せている流れ (セッション本体、または agent) が turn に応答していないと hooks module が言っている間、TL の末尾に、最後のターンが終わってからの経過時間を 1 つ出す。本体の TL では module の `turn.state` が `idle` の間 (DR-0035 §3) で、応答中の間は出さない (応答中の行 `TurnResponding` が出る)
- agent (subagent / teammate / workflow の agent) の TL にも同じ表示を出す。根拠は、module が送る走行中の loop の一覧 (session status の `subagents`、DR-0039 §6) で、これは agent id 付きの `turn.start` / `turn.complete` から作られ、subagent と in-process の teammate の turn の間だけ載る。終わった subagent と仕事待ちの teammate は載らない:
  - subagent: 一覧があり、その agent id が無い間に出す。終わった subagent の TL でも、最後の行からの経過時間が出る
  - teammate: TL は名前で指すので、agent tree の teammate の節が持つ agent id で一覧を引く
  - workflow の agent: run の記録 (state json か journal の `result` の行) がその agent を `done` / `error` と言い、一覧に無い間に出す。workflow の agent が一覧に載ることは確かめていないので、一覧に無いことだけでは終わったと見なさない
  - 一覧が無い (module の無いセッション、module がまだ言っていない)、session status がまだ届いていない、teammate の名前に当たる節が無い時は出さない。本体の `turn` は agent の状態を言わないので、本体が `idle` でも agent の表示の根拠にしない
  - agent の TL には応答中の行は無い (応答中の行は本体の turn の中断のボタンを持つ)。agent が動き出す (一覧に載る) と表示が消え、開いている間に行が届けば起点が新しい最後の行に移る
- 見た目は §2 の空きの表示と同じ部品・同じ CSS (`.tl-elapsed`、点線の縦の継ぎ目と小さな文字)。どちらも「前からどれだけ時間が経ったか」を言う表示なので、末尾用の別の見た目を持たない。末尾では下に続く項目が無いので、下側の継ぎ目だけを描かない。寄せ方だけを印の種類 (`data-tl-marker`) で分け、末尾は文字を TL の左端 (assistant の吹き出しの左端) に寄せ、上側の継ぎ目をその主の語 (`1分`) の左右の中央に置く (kawaz 2026-11-25「: の左右位置だけどその下の 1分 とか少し大きめフォントで出てるやつにたいして左右中央の位置あたりにある方が見やすい。今だと左の壁際に謎の線があるみたいに見えちゃう」)。主の語と括弧の中を語の幅に追従する列に分け、継ぎ目を主の語の列の中央に置く (CSS の grid と subgrid。script で幅を測らない)。文字を左に寄せるのは、右下に浮く入力欄の FAB (`.session-input-fab`) に文字が隠れないため。空きは項目の間にあって FAB とは重ならないので中央寄せのまま
- TL の末尾に置く表示 (末尾の経過時間、§1 の今日の帯、応答中の行) は、行の列 (`.tl-lines`) の最後の子として会話の最後の行の続きに、項目と同じ並びの中に置く (今日の帯が項目の上へ動けるように)。TL の下の空白 (最後の行が FAB や画面の下端に隠れないための余白) は行の列の `padding-bottom` で、末尾の表示はその上に来る。一番下までスクロールすると、末尾の表示の下に空白が残り、TL の下のミニパネル (行の列の後ろ) はその空白の中に引き上げて描かれる
- 文言は `3時間（3h20m）`: 前半は経過のいちばん大きい単位だけを日本語で (切り捨て。1 日以上は `N日`、1 時間以上は `N時間`、1 分以上は `N分`、それ未満は `N秒`)、括弧の中は `formatDuration` の表記。1 分未満は括弧が前半と同じことしか言わない (`12秒` と `12s`) ので括弧を出さない。「最後のターンから」の語は出さない (末尾にあることと見た目で分かる)。支援技術には `最後のターンから3時間20分` の文を名前にする
- いつ終わったかは、読み込まれている transcript の最後の時刻を持つ行の時刻にする。turn の行は turn が終わる時に書かれるので、最後の行の時刻が最後のターンの終わりになる。module の言う `idle` の `since` は使わない: module はセッションの始まり (resume を含む) と `/clear` でも `idle` にし、その時の `since` は module の読み込みの時刻なので、resume した直後のセッションでは「最後のターンから」ではなく「resume から」の時間になる。SESSIONS の行の経過時間 (`last_activity_at`、DR-0053) も timestamp を持つ行の最大から埋まるので、同じ源になる
- module の無いセッション (session status に `turn` が無い)、session status がまだ届いていない間は出さない。分からない時に推測で埋める別の仕組み (最後の行から一定時間たったら終わったと見なす等) は作らない
- 表示したまま 1 秒ごとに進む (応答中の行と同じ `useSecondTick`)
- **本体が待っている agent の数** (kawaz 2026-11-24「メインが何かを待ってるのか単にとまってるのかの見分けとして、最後に出てる `⚫︎ 1 active agent[s]` `1分（1m23s）` みたいなのを出す」「時間が day 系の仲間のパーツだよ」「workflow の run を待ってるなら出すんじゃね？」): 本体の TL の末尾の経過時間が出ている間で、そのセッションの teammate・subagent・workflow の run のうち動いているものが 1 つ以上ある間だけ、経過時間の上の点線の継ぎ目のさらに上に、動いていることを示すドットと `1 active agent` / `2 active agents` (1 の時だけ単数) の行を出す (`● 2 active agents`)。本体が応答中の間は経過時間ごと出ないので、これも出ない
  - 数は Timeline のエージェントのリスト ([DR-0025](./DR-0025-workflow-drilldown.md)) と同じ session status の `agent_tree` から、リストと同じ分け方で数える。Agents の節 (teammate と subagent をまとめた節) は、最上位の行のうち `active` の区画 ([DR-0020](./DR-0020-session-status-tab.md) Addendum 2026-11-06。自分か配下の agent の state が `active` / `running` / `progress` / `spawned`) に入るもの。`spawned` は起動の指令で動いている teammate で、2 度目以降の指令で動いている `active` と同じに数える (kawaz 2026-11-24「live と spawned は初期プロンプトで動いてるか一度ターンが終わって 2 度目以降の指令で動いてるかの違いしかない」)。Workflows の節は live の側の run で、1 つの run を 1 と数え、run の中の agent は数えない。仕事待ち (`idle`) の teammate と完了したものは数えず、配下の agent は親の行に含めて別に数えない
  - module の走行中の loop の一覧 (`subagents`) は数に使わない。仕事待ちの teammate が載らない点は合うが、workflow の agent が載るかは確かめていない (上の agent の TL の項)
  - agent の名前と hover の説明は出さない。agent の TL では出さない (そこの経過時間は agent のもの)
  - 頭のドットは、エージェントのリストの働いている行のドットと同じ部品 (`dotProps("active")` の class、`.status-teammate-dot-active`) で、色 (`--success`) と脈打つ動き (`status-teammate-pulse`)、動きを減らす設定で止まることもそれに従う (kawaz 2026-11-24「動いてるのを見て安心するため」)。この表示のための色や動きは持たない
  - 経過時間と同じ部品の中に、上から「agent の数の行」「点線の継ぎ目」「経過時間」の順に並べる。行は左寄せで、TL の左端 (経過時間の文字と同じ左端) から始まる (kawaz 2026-11-25「N active agents / : / 1分 () とかの位置の方が良い」)
  - ドット・文字・その間の大きさは応答中の行 (`.tl-turn-responding`) と同じにする (kawaz 2026-11-25「同じ位置に応答中… みたいなカウントアップが表示されるやつと同じサイズで良い」)。文字は TL の地の字の大きさ、ドットは応答中のドットと同じ大きさの丸、間は応答中の行と同じ。文字の色は印の色 (応答中の行と同じ弱い色)。新しい色・面・枠は持たない。文字は経過時間の文言と同じく属性 (`data-label`) から生成内容で描き、選択とコピーに入らない
  - 行はボタンで、押すと Timeline のエージェントのリストが、セッションのヘッダの ☰ (`SessionPaneToggle`、[DR-0025](./DR-0025-workflow-drilldown.md) §6) を押した時と同じ状態・同じ覚え方で開閉する (kawaz 2026-11-25「開くボタンが遠くて面倒」)
  - 行が出ている間、末尾は 1 行分高くなる。出入りした時、末尾にいる読み手は末尾に留める: 末尾を保持している間は保持が一瞬で寄せ直し、読み手が自分で最下部まで来た時 (保持が無い) は行が足された時の末尾追従と同じ条件 (位置を張っていない、最下部付近、smooth で動いている途中でない) で一瞬で末尾へ寄せる (`useStickToBottom` の `endShape`。scroll anchoring の無い WebKit では寄せないと出た行の分だけ末尾が隠れる)。遡って読んでいる間は動かさない
- フィルタの間は応答中の行と同じく隠す

### 5. 会話の行ではないこと

帯・空き・末尾の経過時間は会話の行として数えない:

- 位置 (`data-timeline-uuid`) を持たず、クリックで位置を選ばない (帯の日付の部分は押しても何も起きない。動くのは §9 の矢印だけ)。位置の着地・読書位置の記録 (`usePositionPin`) は位置を持つ行だけを見る
- 種類 (`data-notif`) を持たず、🔔🔐 の未読・既読・「全て既読」に入らない (どれも行のデータから数え、DOM を数えない)
- `ItemRawToggle` で包まず、jsonl のトグル、☰ のメニュー、fold を持たない
- TL 内検索の単位を登録せず、検索の一致に入らない
- 選択・コピーに入らない: 文言と矢印の記号は DOM の文字でなく、`data-label` (括弧の中は `data-detail`) から CSS の生成内容 (`content: attr(data-label)`) で描く。WebKit (Safari) は `user-select: none` の文字も、またいだ選択に入れる (WebKit 27.2 でドラッグの選択に帯と空きの文言が入った。Chromium は入れない)。生成内容はどちらのエンジンでも選択に入らない。`user-select: none` も付け、印の上から選択を始めない
- 過去分を「上に読み込む」時に保つ行 (`firstRowScrollAnchor`) に選ばない (印は `data-tl-marker` で名乗る)。先頭の帯は読み込んだ分の先頭へ移るので、保てない
- フィルタを外す時に保つバブル (`filterScrollAnchor`、`data-notif` を持つもの) にならない
- 末尾追従は scroller の大きさの変化で寄せ直すので、末尾に印があっても追従は同じに動く
- 支援技術には `role="separator"` で区切りとして伝え、文言を `aria-label` で名前にする (separator の子は presentational なので、名前を明示する)。帯では separator は日付の要素 (`<time>`) だけで、矢印のボタンはその兄弟に置く (separator の中に置くと、子が presentational になってボタンが支援技術から消える)。末尾の経過時間は毎秒変わるので live region (`role="status"`) にしない

TL にはキーボードで行を移る仕組みが無いので、そこから外す手当ては要らない。

### 6. フィルタの切り替えで描き直さない

- 帯と空きは、TL 全体、🔔 のフィルタ、🔐 のフィルタの 3 つの見方それぞれで決め、全部を描いておく。各印は自分の入る見方を `data-tl-views` (空白区切りの `all` / `say` / `permit`) で名乗り、app.css が今の見方のものだけを出す。同じ項目の帯は見方によらず同じ日付なので 1 つの要素にまとめ、空きは長さが同じなら 1 つにまとめる
- これで DR-0050 §5 の「フィルタは CSS で隠すだけで描き直さない」を、帯を足した後も保つ (フィルタを外す時の位置合わせが測る要素が同じ DOM のまま)
- フィルタだけの吹き出し (窓の外の say / 許可依頼) は今どおりフィルタの間だけ描かれるので、それを含む見方の印もその間だけ変わる

### 7. 重さ

- 印は `.tl-lines` (1 列の grid) の行として素直に置き、絶対配置・anchor を使わない ([findings 2026-11-15-timeline-base-cost](../findings/2026-11-15-timeline-base-cost.md))
- 項目の始まりと終わり (`Date.parse` と暦日) は項目のオブジェクトごとに 1 回だけ求めて持つ (`WeakMap`)。group は live tail の追記と過去分の読み込みで変わらなかった分が同じオブジェクトのままなので (useTranscriptModel.ts)、追記で求め直すのは足された group だけ。印の判定は項目の並びが変わった時 (groups、合流する吹き出し) だけ走り、毎回の描画では走らない

### 8. 祝日の供給元

- holidays-jp (`https://holidays-jp.github.io/api/v1/<年>/date.json`)。内閣府の公表に基づく 1 年分の祝日を `{"YYYY-MM-DD": "名前"}` で返す。key が年月日なので、帯の暦日をそのまま引ける (同じ API の `datetime.json` は key が JST の 0 時の unix 秒で、日付に戻す変換が要るだけ)。祝日の供給元 選定判断基準日: 2026-11-17
- webui (ブラウザ) から直接 `fetch` する。取るのは TL に帯として出た年の分だけで、同じ年はページを開いている間に 2 度取らない
- 年ごとのデータを localStorage (`ccmsg.japanHolidays.<年>`) に期限を付けずに保存する (kawaz 2026-11-17「この程度のデータならその年初めてのときに取得して localStorage に期限なしで保存しておいても良い」)。帯は保存してある値をすぐ使う (取りに行くのを待たず、オフラインでも名前が出る)。保存の無い年は、その年が初めて帯に出た時に取りに行って保存する
- 終わった年 (ブラウザのローカルの今年より前) のデータは確定なので、保存があれば二度と取りに行かない。今年とそれより先の年は、保存があればそれをすぐ使った上で、ページを開いている間に 1 回だけ取り直し、中身が変わっていたら保存と表示を替える (年の途中の法改正で祝日が変わった時に、古い保存が残り続けないため。日数の期限は持たない)。取り直しに失敗したら保存の値のまま使う
- 404 (API が持っていない年) とスキーマに通らない応答は保存しない。localStorage から読んだ値も境界としてスキーマに通し、読めない値 (壊れた値、別の形の値) は無いものとして取り直す。localStorage が例外を投げる環境では保存なしで動く (`storage.ts` の `readStorage` / `writeStorage`)
- 要求に載せるのは年だけ。cookie を送らず (`credentials: "omit"`)、referrer を送らない (`referrerPolicy: "no-referrer"`。webui の URL はセッションを名指す)
- 応答は境界で valibot のスキーマ (key が `YYYY-MM-DD` の日付、値が文字列の record) に通す。通らない応答は丸ごと祝日なしとして扱う
- 保存が無く、取れるまでと取れなかった時 (オフライン、期限切れ、404 = データの無い年、スキーマに通らない) は、祝日の名前を出さずに日付と曜日だけの帯にする。帯の表示を fetch に待たせず、取れたら名前が足される。失敗を見せる表示は無く、失敗した年はページを開いている間取り直さない
- 名前はデータの言う文字列のまま出す (`憲法記念日 振替休日`、`国民の休日`)
- webui の応答には CSP が無く (CSP は sandbox の配信だけ、DR-0030)、この origin への `fetch` を止めるものは無い。holidays-jp は `access-control-allow-origin: *` を返す

Design rationale: 祝日を自前の計算式 (春分・秋分の近似式、振替休日の規則) で持たない。特例の年 (2019〜2021 の移動、即位の日等) を外し、法改正のたびに直すことになる。npm のパッケージも足さない (kawaz 2026-11-17): 公表の度に依存の更新が要り、bundle が増える。

### 9. 帯の ↑ / ↓

- 札の中、日付の左に ↑、右に ↓ のボタン (`<button type="button">`、名前は「前の日付へ」「次の日付へ」) を置く。キーボードで届き、Enter / Space で動く。押せる大きさは 2rem、タッチの端末 (`pointer: coarse`) では 2.75rem (44px、WCAG 2.5.5)
- 見方の全ての項目より上にある帯 (その見方の最初の項目の上の帯) の ↑ は、飛ぶ先も読み足す過去分も無い時に出さない: TL 全体と agent の TL では読み込んだ範囲が transcript の先頭から始まっている時、フィルタの見方では常に (フィルタは全ての say / 許可依頼を出している、DR-0050 §5)。まだ読んでいない過去分がある間は出す (押すと下の決まりで読み足す)。帯は自分が一番上にある見方を `data-tl-top` で名乗り、行の列は先頭から読み込んでいる間 `data-at-start` を持ち、app.css が今の見方の分だけ隠す (§6 と同じく、フィルタの切り替えで描き直さない)。隠すのは `visibility: hidden` で、場所は残す: 札の幅と日付の位置が ↑ の有無で揺れず、日付は ↓ と左右対称の位置に留まる。隠れたボタンはフォーカスも支援技術も受けない
- ↑ は 1 つ上の帯へ、↓ は 1 つ下の帯へ飛ぶ。飛ぶ先は今の見方 (TL 全体か、フィルタのバブル) に出ている日付の帯だけで、空きの表示は飛び先にしない。「飛ぶ」は位置への着地と同じく、帯をツールバーの直下に置いて保つこと (`toolbar-offset.ts` の `topBelowToolbar` と `useScrollHold` の `toElement`)。押した後のフォーカスは、飛び先の帯の同じ向きの矢印に移す (続けて押して日をたどれる)
- 飛ぶ時 (読み込み済みの帯へ、読み足して見つけた帯へ、端の ⤒ / ⤓ 相当) は、どちらへ動いたかが目で追えるよう短い smooth で動かす。読み足しの間の位置の保持は一瞬 (DR-0056)
- ↑ で上に帯が無ければ、「過去分を上に読み込む」と同じ経路 (今の先頭の行を保つ寄せ方と、押したボタンの「読み込み中…」も同じ) で 1 ページずつ読み足しながら探す。transcript の先頭まで読んでも無ければ (押した帯が最初の日)、⤒ と同じく TL の一番上へ。フィルタの間は読み足さない (フィルタは全ての say / 許可依頼を出している、DR-0050 §5) ので、上に無ければ一番上へ
- ↓ で下に帯が無ければ、⤓ と同じく TL の末尾へ。末尾の今日の帯 (§1) も帯なので、その上の帯の ↓ はそこへ飛ぶ。読み込まれている範囲は常に transcript の終わりまでを含む (窓の外の位置は head に戻る、`usePositionLanding`) ので、下に読み足すものは無い
- 読み足しながらの探索は、他のことが起きたら手放し、後から位置もフォーカスも動かさない: 別の押下 (どの帯の矢印でも)、読み手自身のスクロール (wheel / touch / キー / scrollbar、末尾追従が読み手の操作として拾うもの)、フィルタの切り替え、セッションの切り替え
- 押した帯が読み足しで消えた時 (上に同じ日の行が入り、その日の帯が上へ移った時) は、その日付の帯から数える

### 10. 末尾の「↑最新のプロンプトへ移動↑」

kawaz の依頼 (2026-11-22): 最新の自分の発言へ戻るのに、ヘッダの 👤 (DR-0058 §11) では 2 手かかる。TL の末尾から 1 手で戻れるようにする。

- **置き場**: 末尾の並び (§1) の一番下、Waiting... の行 ([DR-0059](./DR-0059-timeline-waiting-notice.md)) の下。ユーザの発言の吹き出しと同じく右に寄せる (行の列の内側の右端)。DOM では行の列の最後の子に置く
- **行の列の流れに高さを持たせない** (kawaz 2026-11-24: 流れに入れず、置いている場所の手前の項目の下端に浮かせる。左右は今のまま): ボタンは `position: absolute` で、行の列 (`.tl-lines`、`position: relative`) を基準の箱にして浮かせる。縦は、手前に描かれている行の下端から行の間の gap だけ下 (流れの中に置いていた時と同じ位置)。ボタンを除くと行の列の中身の下端は手前に描かれている行の下端なので、末尾の余白 (`--tl-lines-end-space`、`padding-bottom`) の上端から gap だけ下に置く。隠れている行は数えない。横は今のまま行の列の内側の右端。出ても隠れても行の列の高さと、その下の一番下の状態の行 (`.tl-bottom-controls`、末尾の余白の中に引き上げて描く) の位置は変わらない。流れの中に置くと、ボタンが箱を自分の分だけ下へ押し、箱が表示領域の下端から押す分より浅く入っている所で、出ると箱が外れて消え、消えると戻って出るのを毎フレーム繰り返した (2026-11-24 に Chromium と WebKit で確認)。浮いたボタンは末尾の余白の上端の位置に描かれ、余白の中の状態の行・右下の FAB とは重ならない (幅 390 と 1280、最下部と 10・30px 上、末尾の経過時間・今日の帯・応答中の行・Waiting の行がある時で確認)
- **出す時** (kawaz 2026-11-24): 最新のプロンプトが表示領域に入っておらず、かつ TL の一番下の状態の行のある箱 (`.tl-bottom-controls`) が表示領域に入っている間だけ出す。TL を遡って読んでいる間 (一番下が見えていない) は出さない。フィルタの間も出さない
- **文言と見た目**: `↑最新のプロンプトへ移動↑` (「過去分を上に読み込む」と同じく、矢印と文字の間に空白を置かない)。見た目は許可依頼の「既読」・フィルタの「全て既読」と同じ枠だけの丸いボタン (`.permit-read` と同じ規則、`.tl-latest-prompt`)。新しい色は足さない
- **最新の発言**: 読み込み済みの範囲 (窓) の境界の行のうち、ユーザの発言の吹き出しで描くもの (`classifyBoundaryLine` の `user-prompt`、👤 のフィルタと同じ範囲) で位置 (uuid) を持つ最も新しいもの。窓の外は探さない: TL に出ていない発言は読み手にとって無いのと同じで、TL に乗っている最新へ移れば足りる (kawaz 2026-11-22)
- **出す条件**: 最新の発言が TL の表示領域 (scroller の見えている範囲のうち sticky な toolbar の下) に 1px も入っていない時だけ出す。見えているかは、その発言の項目の要素を IntersectionObserver で見張り、知らせの値から描画で導く (スクロールの event を測らない、タイマーで待たない。`useItemInView`)。知らせがまだ来ていない間は出さない。行の要素は作り直されることがあるので、描いている内容が変わるたびに要素を探し直す
- **出さない所**: 窓に発言が 1 つも無い TL、subagent / teammate / workflow の agent の TL (ボタンはセッションの発言へ戻るもの)、フィルタの間 (🔔🔐⭐👤🔍)。フィルタの間は要素をそのまま hidden で隠し、フィルタの切り替えで行の列を描き直さない (§6)
- **押した時**: フィルタの項目のクリックと同じ「TL に移動」(DR-0058 §6) でその発言の位置 (`seek=true`) へ replace で移り、TL 表示領域の一番上に着地させる。押した操作なので短い smooth (DR-0056)。着地すると発言が見えるので、ボタンは自然に消える。位置へ移るので、他の「TL に移動」と同じく末尾追従はやめ、読み手が最下部へ戻った時に位置を外して追従に戻る
- **会話の行ではない**: §5 の印と同じく、位置・種類 (`data-notif`) を持たず、既読・検索・選択・jsonl・fold・過去分を読み込む時に保つ行のどれにも入らない
- **末尾追従**: ボタンが出る・消えても行の列の高さは変わらないので、末尾追従の寄せ直しは起きない

### 11. 表示領域の下の中央の「↓先頭に移動↓」

kawaz の依頼 (2026-11-23): ツールバー右端の ⤓ は遠くて押しにくいので、画面の下側にも最下部へ移るボタンを置く。

- **文言と見た目**: `↓先頭に移動↓` (kawaz の書いた文言のまま。§10 の「↑最新のプロンプトへ移動↑」と対になる形で、矢印と文字の間に空白を置かない)。見た目は §10 と同じ部品 (`.permit-read` と同じ規則に `.tl-bottom-pill` を足し、地・枠・文字の色もユーザの発言の吹き出しに合わせる)。新しい色は足さず、浮いていることが分かる影だけを付ける。字の大きさは 2 つのボタンとも TL の本文と同じ (`--font-size-2xl`。kawaz 2026-11-25「妙に小さい、普通サイズのフォントで良い」)。形を借りている `.permit-read` の小さな字にはしない
- **押した時**: ツールバーの ⤓ と同じ関数 (`scrollToBottom`、`scrollHold.toBottom("user")`) を呼ぶ。操作が起点なので短い smooth (DR-0056)。末尾に着くと、ボタンは自然に消える
- **出す条件**: 並びの末尾 (行の列の後ろ、scroller の直下) に置いた高さ 0 の番兵 (`.tl-tail`) が、scroller の表示領域に入っていない間だけ出す。番兵は末尾の並び (§1) の後ろにあるので、最後の項目も末尾の経過時間・今日の帯・応答中の行・「↑最新のプロンプトへ移動↑」も含めて下端が画面外の時が対象になる。見えているかは IntersectionObserver (root は scroller、番兵を見る。`useTailInView`、§10 の `useItemInView` と同じ仕組み) の知らせから描画で導き、スクロールの event は測らない。丸めで番兵が小数 px だけ下に残る分の余裕として、表示領域の下端を 2px 広げて判定する。知らせがまだ来ていない間は出さない。行の要素が作り直されても番兵は同じ要素のまま
- **状態の行が見えている間は出さない** (kawaz 2026-11-24): TL の一番下の状態の行のある箱 (`.tl-bottom-controls`) が表示領域に入っている間は、末尾の番兵が入っていなくても出さない。そこまで下に来ていれば末尾へ飛ぶ意味が無く、§10 の「↑最新のプロンプトへ移動↑」(状態の行が見えている間だけ出る) と同時に出ることも無くなる
- **置き場**: scroller の末尾に置いた高さ 0 の `position: sticky; bottom: 0` の台 (`.tl-bottom-pill-slot`) の中で、ボタンを台の上へ張り出し (`position: absolute`)、左右の中央、表示領域の下端から `--space-9` の所に浮かせる。スクロールでは動かない。scroller は `#app` が縮む (ソフトウェアキーボード、アドレスバー) と一緒に縮むので、台がその下端に貼り付くボタンは隠れもずれもしない (fixed の部品と違い visualViewport の追従は要らない)。右下の FAB (`.session-input-fab`) とは、中央と右で並ぶので重ならない
- **フォーム・パネルとの重なり**: セッションの入力欄 (`.session-input-panel`) が開いている間と、見ているタブの TL でコメントのフォームが開いている間は、FAB と同じく出さない (幅 390 では FAB の列に重なり、広い幅でも中央に及ぶ)。範囲選択の 💬 のボタンが避ける矩形 (`floatingBoxes`) にこのボタンを含める
- **出す所**: ⤓ があるところ全て。フィルタの見方 (🔔🔐⭐👤💬🔍) と agent の TL でも、同じ条件で出す
- **会話の行ではない**: §10 と同じく、行の列の外にあり、位置・種類 (`data-notif`) を持たない

| 案 | 採らない理由 |
|---|---|
| フィルタの間は帯を出さない (TL 全体の帯を隠すだけ) | フィルタの間は帯が無く、何日のバブルか分からない。kawaz の「表示されない行は数えない」に合わない |
| フィルタを切り替えるたびに、その見方の帯を描き直す | DR-0050 §5 の「描き直さない」を破る。フィルタを外す時の位置合わせが測る DOM が変わり、既存のテスト (外しても全ての要素が同じ) が固定している決まりに反する |
| 末尾の経過時間を module の `idle` の `since` から出す | §4。resume・`/clear` の直後は「最後のターンから」にならない |
| 「↑最新のプロンプトへ移動↑」を流れの中に置いたまま、隠している間も高さを残す (`visibility: hidden`) | 行の列の末尾にボタンの分の空きがいつも残る (新しい見た目)。箱がその分下にあるので、最下部から少し上 (確認では 10〜30px) ではボタンが出ず「↓先頭に移動↓」が出る |
| ボタンを流れの中に置いたまま、出ている間は箱を見張る IntersectionObserver の表示領域の下端をボタンが押す分だけ広げて打ち消す | 振動は止まるが、ボタンが出ている間に箱がボタンに押されて表示領域の外にあることがあり、「箱が入っている間だけ出す」と字面で食い違う。押す分を測る処理と、見張りを出入りの直後に張り直すための layout effect が要る。浮かせれば押すこと自体が無くなる |
| ボタンの縦の位置を CSS anchor positioning で手前の行の下端に付ける | 手前の行を選ぶ selector が行の列の行に効いて重い。1007 行の TL で、全ての行に `anchor-name` を付けると Chromium の layout が 1 回約 100ms から約 1770ms に、付ける行を絞っても行を 1 つ足す時の WebKit の再計算が約 3ms から約 40ms (ボタンの手前の 2 つ、`:has(+ …)`) ・約 2200ms (最後の項目とその後ろ、`:nth-last-child(1 of …) ~`) になった。末尾の余白の上端から置けば同じ位置になり、どちらも使わない |
| 帯を `position: sticky` にして今の日を上に貼る | TL の行に positioned な子を増やすと WebKit で行数の 2 乗の layout になる (findings 2026-11-15)。先頭の帯 (§1) で今の日は分かる |
| fold group の中の行の間にも帯を置く | fold group は 1 つの項目で、中身は memo された別の component が描く。日をまたぐ fold の始まりと次の項目で境目は分かる |

## Consequences

- TL を開いたページでは、帯に出た今年以降の年と保存の無い年ごとに holidays-jp へ 1 回の要求が出る。外へ出られない環境では、保存の無い年の祝日の名前が出ないだけで、他は変わらない
- localStorage に年ごとの祝日 (1 年 1KB 弱) が溜まり、消さない
- 帯と空きは 3 つの見方の分を描くので、フィルタの見方の印 (say / 許可依頼の数に比例) の分だけ要素が増える
- 末尾の経過時間は 1 秒ごとに文言を書き換える。822 行の TL で、書き換えと強制した layout は Chromium で約 2ms、WebKit で 4〜5ms (2026-11-17 の確認)
- 印を足した前後で、fold の開閉と live の追記は Chromium で 18〜32ms、WebKit で 27〜62ms のまま (印の layout を CSS で外した時と差が無い)。印の判定の計算は 3 つの見方で 1 回あたり約 0.24ms (初回の暦日の計算込みで約 1.5ms)
- 帯の ↑ / ↓ で飛ぶのは smooth の長さが加わる (DR-0056 の Consequences: WebKit は約 0.2 秒、Chromium は距離で伸びて 1.5 秒で頭打ち)。読み足しが要る時は、読み込み (1 ページで Chromium 約 150ms、WebKit 約 230ms) の後に smooth で動く
- ブラウザの timezone は開いた時のものを使う。開いている間に端末の timezone を変えても、読み直すまで帯は前の timezone の暦日のまま
