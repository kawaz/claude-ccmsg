# DR-0054: TL の日付の帯と空きの表示、末尾の最後のターンからの経過時間

- Status: Accepted (2026-11-17、kawaz 指示) — ✅ 実装済み (`timeline-day-marks.ts` の `calendarDayOf` / `itemSpanOf` / `dayMarksOf` / `dayLabel`、`japan-holidays.ts`、`components/timeline/useDayMarks.ts` の `shownItems` / `useDayMarks` / `lastRowTime`、`components/timeline/DayMarks.tsx` の `DayBand` / `DayGapMark` / `TurnIdleMark`、app.css の `.tl-day` / `.tl-day-gap` / `.tl-turn-idle` と `data-tl-views` の規則)
- Date: 2026-11-17

## Context

TL の項目は時刻 (吹き出しの足の `HH:MM:SS` と相対時間) を持つが、流し読みでは日の境目が分からない。何日も空いたセッションを開くと、どこから別の日の話かを時刻を 1 つずつ読んで探すことになる。終わったセッションの TL の末尾からは、最後のやり取りからどれだけ経ったかも分からない。kawaz の指示 (2026-11-17) の要点:

> webuiのTL上に、日付の区切り部分に目立つ帯(widthwideな文字配置はセンターなボックス？)を挿入してください。2026年11月16日とかで良い。

> アイテム間の日付ズレが1日なら日付のみ

> アイテム間の日付ズレが2日以上なら した側アイテムの上に同じく日付のみのwideバーを置いて。それプラスその上側に前のアイテムからの間日数が分かることを表示するアイテムを挿入する。

> TLの一番下、最新のターンが終わっている場合、最終ターンからの経過時間を表示するアイテムを一つ表示しておく。

続けて帯の表記に曜日と祝日 (「（月）のような感じの曜日も。ついでに祝日なら。更に曜日の横に（月、XXの日）のように祝日の名前も」)、祝日の供給元に holidays-jp の API の指定があった。

## 目的

TL を流し読みする人が、日の境目、何日も空いた所とその長さ、最後のやり取りからの経過を、項目の時刻を読まずに分かる。

増やしたくないもの: 会話の行として数えられるもの (既読、バッジ、検索、選択、位置、末尾追従、行のメニュー・jsonl・fold)。帯は会話の行の間に置く印で、会話の行の振る舞いを 1 つも持たない。

## Decision

### 1. 日付の帯

- TL に並ぶ隣り合う 2 つの項目が違う暦日に始まる時、下 (新しい側) の項目の真上に、TL の幅いっぱいの帯を 1 つ置く。帯は幅いっぱいの罫の中央に、accent で塗った日付の札を置く形で、下の項目の日付を出す (fork の境目の細い罫と淡い文字より強く、吹き出しとも紛れない。罫の面を薄く敷く形と比べ、dark で沈まない方を採った)
- 暦日はブラウザのローカルの暦日 (ブラウザの timezone の時計が示す年月日)。24 時間ごとに区切らない: 夏時間の切り替えで 23 時間・25 時間の日も 1 日と数える
- 読み込まれている範囲の最初の項目の上にも、その項目の日付の帯を置く (今見ている所が何日かが分かるように)。過去分を読み込んで先頭が変わったら、帯は新しい先頭の上に移り、元の先頭は上の項目と日が違えば普通の帯を持つ
- 表記は `2026年11月16日（月）`。その日が日本の祝日なら `2026年11月23日（月、勤労感謝の日）` のように曜日の後ろに読点で祝日の名前を足す。括弧は全角。日付と曜日は `Intl.DateTimeFormat` (ja-JP) で組み、自前の曜日の表を持たない
- 祝日は帯の暦日 (ブラウザのローカルの暦日) で日本の祝日表を引く。ブラウザの timezone が日本でなくても、日本の日付に直さずにローカルの暦日のまま引く

### 2. 空きの表示

- 上の項目の終わりの暦日から下の項目の始まりの暦日までが 2 日以上の時、帯の上に空きの表示を 1 つ足す。並びは上から「上の項目 → 空き → 帯 → 下の項目」
- 文言は `3日ぶり（2d14h 空き）`: 暦日の差と、上の項目の終わりから下の項目の始まりまでの時間 (TL の経過時間と同じ `formatDuration` の表記)。見た目は帯の上の、点線の縦の継ぎ目で挟んだ控えめな文字 (面を持たず、間が飛んでいることを線の途切れで表す)
- 1 日だけ違う時 (夜をまたいだだけ) は帯だけ

### 3. 項目と、その時刻

- 判定は TL に実際に表示される項目の並びに対して行う。表示される項目は `.tl-lines` の直下に描かれる会話の項目で、境界の行 (人の発話、応答、say、許可依頼、ccmsg 等) の吹き出しと fold group、時刻で合流する吹き出し (worker の say、フィルタ中の窓の外の say / 許可依頼)。何も描かない境界 (描く吹き出しが別の所にある ccmsg) は数えない
- fold group は中身が開いていても閉じていても 1 つの項目で、中の行の間には帯を置かない。fold group の始まりは時刻を持つ最初の行、終わりは最後の行。帯の要否と日付は項目の始まりで決め (隣の項目と始まりの暦日が違えば帯)、空きは上の項目の終わりから測る。日をまたいで続いた fold group の次の項目は、新しい日の帯を持つが、空いた日は無いので空きを持たない
- 時刻は各行の `timestamp` (TL の行の `ts`)。時刻を持たない項目 (読めない行だけの fold) は判定で飛ばし、その上下の項目どうしを比べる
- フィルタ (DR-0050 §4) の間は、そのフィルタに残るバブルの並びで決める。フィルタで隠れる行は数えない

### 4. 末尾の最後のターンからの経過時間

- そのセッションの hooks module が、本体が turn に応答していない (`turn.state` が `idle`、DR-0035 §3) と言っている間、TL の末尾 (応答中の行の場所) に、最後のターンが終わってからの経過時間を 1 つ出す。文言は `最後のターンから 3m12s`。応答中の行と同じ場所・同じ並びで、点だけを中抜きにする (turn が始まると同じ位置で脈打つ塗りの点の応答中の行に替わる)。応答中の間は出さない (応答中の行 `TurnResponding` が出る)
- いつ終わったかは、読み込まれている transcript の最後の時刻を持つ行の時刻にする。turn の行は turn が終わる時に書かれるので、最後の行の時刻が最後のターンの終わりになる。module の言う `idle` の `since` は使わない: module はセッションの始まり (resume を含む) と `/clear` でも `idle` にし、その時の `since` は module の読み込みの時刻なので、resume した直後のセッションでは「最後のターンから」ではなく「resume から」の時間になる。SESSIONS の行の経過時間 (`last_activity_at`、DR-0053) も timestamp を持つ行の最大から埋まるので、同じ源になる
- module の無いセッション (session status に `turn` が無い)、session status がまだ届いていない間、agent の TL では出さない。分からない時に推測で埋める別の仕組みは作らない
- 表示したまま 1 秒ごとに進む (応答中の行と同じ `useSecondTick`、`formatDuration` の表記)
- フィルタの間は応答中の行と同じく隠す

### 5. 会話の行ではないこと

帯・空き・末尾の経過時間は会話の行として数えない:

- 位置 (`data-timeline-uuid`) を持たず、クリックで位置を選ばない。位置の着地・読書位置の記録 (`usePositionPin`) は位置を持つ行だけを見る
- 種類 (`data-notif`) を持たず、🔔🔐 の未読・既読・「全て既読」に入らない (どれも行のデータから数え、DOM を数えない)
- `ItemRawToggle` で包まず、jsonl のトグル、☰ のメニュー、fold を持たない
- TL 内検索の単位を登録せず、検索の一致に入らない
- 選択・コピーに入らない: 文言は DOM の文字でなく、`data-label` から CSS の生成内容 (`content: attr(data-label)`) で描く。WebKit (Safari) は `user-select: none` の文字も、またいだ選択に入れる (WebKit 27.2 でドラッグの選択に帯と空きの文言が入った。Chromium は入れない)。生成内容はどちらのエンジンでも選択に入らない。`user-select: none` も付け、印の上から選択を始めない
- 過去分を「上に読み込む」時に保つ行 (`firstRowScrollAnchor`) に選ばない (印は `data-tl-marker` で名乗る)。先頭の帯は読み込んだ分の先頭へ移るので、保てない
- フィルタを外す時に保つバブル (`filterScrollAnchor`、`data-notif` を持つもの) にならない
- 末尾追従は scroller の大きさの変化で寄せ直すので、末尾に印があっても追従は同じに動く
- 支援技術には `role="separator"` で区切りとして伝え、文言を `aria-label` で名前にする (separator の子は presentational なので、名前を明示する)。末尾の経過時間は毎秒変わるので live region (`role="status"`) にしない

TL にはキーボードで行を移る仕組みが無いので、そこから外す手当ては要らない。

### 6. フィルタの切り替えで描き直さない

- 帯と空きは、TL 全体、🔔 のフィルタ、🔐 のフィルタの 3 つの見方それぞれで決め、全部を描いておく。各印は自分の入る見方を `data-tl-views` (空白区切りの `all` / `say` / `permit`) で名乗り、app.css が今の見方のものだけを出す。同じ項目の帯は見方によらず同じ日付なので 1 つの要素にまとめ、空きは長さが同じなら 1 つにまとめる
- これで DR-0050 §5 の「フィルタは CSS で隠すだけで描き直さない」を、帯を足した後も保つ (フィルタを外す時の位置合わせが測る要素が同じ DOM のまま)
- フィルタだけの吹き出し (窓の外の say / 許可依頼) は今どおりフィルタの間だけ描かれるので、それを含む見方の印もその間だけ変わる

### 7. 重さ

- 印は `.tl-lines` (1 列の grid) の行として素直に置き、絶対配置・anchor を使わない ([findings 2026-11-15-timeline-base-cost](../findings/2026-11-15-timeline-base-cost.md))
- 項目の始まりと終わり (`Date.parse` と暦日) は項目のオブジェクトごとに 1 回だけ求めて持つ (`WeakMap`)。group は live tail の追記と過去分の読み込みで変わらなかった分が同じオブジェクトのままなので (useTranscriptModel.ts)、追記で求め直すのは足された group だけ。印の判定は項目の並びが変わった時 (groups、合流する吹き出し) だけ走り、毎回の描画では走らない

### 8. 祝日の供給元

- holidays-jp (`https://holidays-jp.github.io/api/v1/<年>/date.json`)。内閣府の公表に基づく 1 年分の祝日を `{"YYYY-MM-DD": "名前"}` で返す。key が年月日なので、帯の暦日をそのまま引ける (同じ API の `datetime.json` は key が JST の 0 時の unix 秒で、日付に戻す変換が要るだけ)。祝日の供給元 選定判断基準日: 2026-11-17
- webui (ブラウザ) から直接 `fetch` する。取るのは TL に帯として出た年の分だけで、同じ年はページを開いている間に 2 度取らない
- 年ごとのデータを localStorage (`ccmsg.japanHolidays.<年>`) に期限を付けずに保存する (kawaz 2026-11-17「この程度のデータならその年初めてのときに取得して localStorage に期限なしで保存しておいても良い」)。帯は保存してある値をすぐ使う (取りに行くのを待たず、オフラインでも名前が出る)。保存の無い年は、その年が初めて帯に出た時に取りに行って保存する
- 終わった年 (ブラウザのローカルの今年より前) のデータは確定なので、保存があれば二度と取りに行かない。今年とそれより先の年は、保存があればそれをすぐ使った上で、ページを開いている間に 1 回だけ取り直し、中身が変わっていたら保存と表示を替える (年の途中の法改正で祝日が変わった時に、古い保存が残り続けないため。日数の期限は持たない)。取り直しに失敗したら保存の値のまま使う
- 404 (API が持っていない年) とスキーマに通らない応答は保存しない。localStorage から読んだ値も境界としてスキーマに通し、読めない値 (壊れた値、別の形の値) は無いものとして取り直す。localStorage が例外を投げる環境では保存なしで動く (`storage.ts` の `readStorage` / `writeStorage`)
- 要求に載せるのは年だけ。cookie を送らず (`credentials: "omit"`)、referrer を送らない (`referrerPolicy: "no-referrer"`。webui の URL はセッションを名指す)
- 応答は境界で valibot のスキーマ (key が `YYYY-MM-DD` の日付、値が文字列の record) に通す。通らない応答は丸ごと祝日なしとして扱う
- 保存が無く、取れるまでと取れなかった時 (オフライン、期限切れ、404 = データの無い年、スキーマに通らない) は、祝日の名前を出さずに日付と曜日だけの帯にする。帯の表示を fetch に待たせず、取れたら名前が足される。失敗を見せる表示は無く、失敗した年はページを開いている間取り直さない
- 名前はデータの言う文字列のまま出す (`憲法記念日 振替休日`、`国民の休日`)
- webui の応答には CSP が無く (CSP は sandbox の配信だけ、DR-0030)、この origin への `fetch` を止めるものは無い。holidays-jp は `access-control-allow-origin: *` を返す

Design rationale: 祝日を自前の計算式 (春分・秋分の近似式、振替休日の規則) で持たない。特例の年 (2019〜2021 の移動、即位の日等) を外し、法改正のたびに直すことになる。npm のパッケージも足さない (kawaz 2026-11-17): 公表の度に依存の更新が要り、bundle が増える。

## Alternatives Considered

| 案 | 採らない理由 |
|---|---|
| フィルタの間は帯を出さない (TL 全体の帯を隠すだけ) | フィルタの間は帯が無く、何日のバブルか分からない。kawaz の「表示されない行は数えない」に合わない |
| フィルタを切り替えるたびに、その見方の帯を描き直す | DR-0050 §5 の「描き直さない」を破る。フィルタを外す時の位置合わせが測る DOM が変わり、既存のテスト (外しても全ての要素が同じ) が固定している決まりに反する |
| 末尾の経過時間を module の `idle` の `since` から出す | §4。resume・`/clear` の直後は「最後のターンから」にならない |
| 帯を `position: sticky` にして今の日を上に貼る | TL の行に positioned な子を増やすと WebKit で行数の 2 乗の layout になる (findings 2026-11-15)。先頭の帯 (§1) で今の日は分かる |
| fold group の中の行の間にも帯を置く | fold group は 1 つの項目で、中身は memo された別の component が描く。日をまたぐ fold の始まりと次の項目で境目は分かる |

## Consequences

- TL を開いたページでは、帯に出た今年以降の年と保存の無い年ごとに holidays-jp へ 1 回の要求が出る。外へ出られない環境では、保存の無い年の祝日の名前が出ないだけで、他は変わらない
- localStorage に年ごとの祝日 (1 年 1KB 弱) が溜まり、消さない
- 帯と空きは 3 つの見方の分を描くので、フィルタの見方の印 (say / 許可依頼の数に比例) の分だけ要素が増える
- 末尾の経過時間は 1 秒ごとに文言を書き換える。822 行の TL で、書き換えと強制した layout は Chromium・WebKit とも 1ms 以下で、フレームの間隔は 18ms を超えなかった (2026-11-17 の確認)
- 印を足した前後で、fold の開閉と live の追記は Chromium で 25〜32ms、WebKit で 34〜56ms のまま (印の layout を CSS で外した時と差が無い)。印の判定の計算は 3 つの見方で 1 回あたり約 0.24ms (初回の暦日の計算込みで約 1.5ms)
- ブラウザの timezone は開いた時のものを使う。開いている間に端末の timezone を変えても、読み直すまで帯は前の timezone の暦日のまま
