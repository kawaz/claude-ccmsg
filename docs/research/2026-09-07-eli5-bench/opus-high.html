1

こまった：みんなバラバラ

お手伝いが 4人・5人 になると、線が こんがらがる。

DR-0001「Context」＋ README「rewrite した理由」：1対1しか無いと 組み合わせが 爆発し、同じ指示の コピペや 伝聞の 転送が 増える。

2

まんなかに 係の人

書くのは いつも この人ひとり（デーモン）。

DR-0001 決定 §2「中央デーモン = 単一 writer」：書き込みを 1 プロセスに 集約する。名前も 番号も この人が 決める（§3）。

3

部屋（room）に ひとこと

1回 しゃべると、部屋の みんなに とどく。

DR-0001 決定 §5：本文を 展開済みで push する（あとで 取りに行かせない）。「to」は 呼びかけの 印。DR-0003 決定 §5 で 配送の 形が 決まっている。

4

ノートは 1冊、足すだけ

部屋ごとに 1冊。うしろに 足すだけ。消さない。

DR-0001 決定 §4：room ごとに 1 つの append-only jsonl が 唯一の 永続状態。mid は 追記順の 連番。

5

「読んだ」は 自分で おぼえる

係の人は 覚えない。昔の 掲示板と おなじ。

DR-0001 決定 §6：サーバは 既読 cursor を 持たない。つなぎ直す時は 自分で「ここから」を 伝える（DR-0003 決定 §5 の since 指定）。

6

人も 部屋の 一員

人は「u1」。ぜんぶの 部屋に 最初から いる。

DR-0003 決定 §2：User の id は 予約済みで、member 行 なしで 全 room に 暗黙に 存在する。書く時は「だれか」を 名乗れないと エラー（同 §3）。

7

ブラウザから のぞく

係の人が Web画面も 出す。玄関で ちゃんと 見る。

DR-0004 決定 §1「HTTP は daemon 内蔵」／§2「WS で 同じプロトコル・role を User に 固定（identity pinning）」／§3「bind は loopback、Origin 検証で 審査」。

8

返事の 場所を 教えてくれる

メッセージに「どこに 返す？」の 付箋が 付く。

DR-0014 決定 §2.4・§2.5：応答経路 hint を daemon が 配送時に 刻印し、agent は 推測せず それに 従う。人が ひとりの 相手に 送る「1on1 room」も 同 §2.1。

9

これから：まだ できてない

いまは ひとつ。いくつも つなぐ 話は 相談中。

DR-0001 決定 §1「Single host」が いまの 形。複数 instance を mesh で 束ねる 案は open な issue（受け入れ条件 未チェック）で、まだ 実装されていない。
